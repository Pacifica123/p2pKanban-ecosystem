# Темы интерфейса приложения

## Решение

Во всех направлениях с интерфейсом (web, mobile, abl, launcher) приложение предлагает
одни и те же четыре темы. Это темы **самого приложения**: боковой панели,
форм, диалогов, настроек. Оформление досок (пресеты, обои, акцент) живёт
отдельно и этим словарём не управляется.

| id | Название | Схема | На что похожа |
|---|---|---|---|
| `graphite` | Графит | тёмная | KDE Breeze Dark: тёмно-серая рабочая |
| `lemon` | Лимон | светлая | AppFlowy Lemonade: светло-жёлтая flat |
| `azure` | Лазурь | светлая | Microsoft Word: светло-синяя flat |
| `silver` | Серебро | светлая | стандартная тема AppFlowy: светло-серая flat |

Тема по умолчанию — `graphite`. Прежняя тёмно-синяя тема убрана из всех
направлений (решение владельца, причина эстетическая).

Названия чужих продуктов здесь только ориентир по настроению. Значения цветов
подобраны заново, имена и логотипы этих продуктов в интерфейс не попадают.

## Словарь `p2p-kanban-ui-themes/1`

Источник значений — [ui-themes.json](ui-themes.json). Это общий словарь, а не
контракт обмена: устройства ничего друг другу о теме не передают. Каждое
направление держит у себя собственную копию значений в своём формате и
отвечает за неё само:

| Направление | Где лежит копия |
|---|---|
| web | `web/frontend/src/app/styles/themes.css` |
| mobile | `mobile/src/app/uiThemes.ts` |
| abl | `abl/src/themes.css` |
| launcher | `launcher/launcher_app/themes.py` (со ступени L1) |

Токены (смысл одинаков везде, имена в коде направления могут быть своими):

| Токен | Для чего |
|---|---|
| `background` | фон окна, самый нижний слой |
| `surfaceMuted` | боковая панель и вторичные панели, на ступень выше фона |
| `surface` | панели, формы, диалоги |
| `surfaceRaised` | карточки и приподнятые элементы, самый верхний слой |
| `border`, `borderStrong` | обычная граница; граница полей и выделения |
| `text`, `textMuted` | основной и второстепенный текст |
| `accent` | фокус, индикаторы, выделение |
| `accentStrong`, `onAccent` | заливка главной кнопки и текст на ней |
| `accentSoft` | фон выбранного элемента |
| `accentText` | ссылки и текст цвета акцента |
| `danger`, `success`, `warning` | граница, точка, иконка статуса |
| `dangerText`, `successText`, `warningText` | текст статуса на `surface` |
| `overlay` | затемнение под диалогом |

Минимальные контрасты (WCAG), которые словарь обязан держать:

- `text`, `textMuted`, `accentText`, `*Text` на `background`, `surface`,
  `surfaceMuted`, `surfaceRaised` — не меньше 4.5;
- `onAccent` на `accentStrong` — не меньше 4.5.

Проверка: `python -B tools/ecosystem/check_ui_themes.py`. С флагом
`--directions` она дополнительно сообщает, каких значений словаря не нашлось
в копиях направлений (только предупреждение: направление вправе отставать).

## Где хранится выбор

Выбор темы — настройка устройства и через узел не синхронизируется. Web
хранит его в `localStorage`, mobile — в хранилище телефона (AsyncStorage), оба
под ключом `p2p-kanban.ui-theme`. Неизвестное или пустое значение означает
`graphite`.

abl пока помнит выбор только до перезапуска окна: его фронтенду запрещены
хранилища браузера, всё долговременное живёт за границей Rust core. Запоминание
темы в abl — отдельная карточка на доске.

Поле `appTheme` (`system | light | dark`) в настройках пользователя на узле
остаётся ради старых клиентов: web-узел его по-прежнему принимает и отдаёт,
но новые клиенты по нему тему не выбирают. Поэтому mobile, отстающий от web,
ничего не ломает: старый APK продолжает читать `appTheme`, новый его
игнорирует.

## Порядок обновления

Контракт между направлениями не меняется. Патчи идут web → mobile → abl
только по привычке экосистемы; любой из них работает без остальных.

## Как добавить тему

1. Добавить тему в `ui-themes.json`, пройти `check_ui_themes.py`.
2. Отдельными патчами перенести её в копии web, mobile и abl.
