# Методология учебников

Дата: 2026-10-16. Решения владельца: карточка «Два учебника» на доске.

Здесь записано, **как** пишутся учебники экосистемы. Сами учебники лежат в
[`docs/textbooks/`](../textbooks/README.md). Этот документ правится патчем
экосистемы, учебники — тоже: они общий слой, их читают все направления
([E-ADR-001](adr/E-ADR-001-shared-documentation-layer.md)).

## 1. Три текста и три читателя

| Текст | Читатель | На что отвечает |
|---|---|---|
| Учебник пользователя (УП) | человек, который впервые слышит слово «p2p» | что это за программа, почему она так устроена и как ею пользоваться |
| Учебник разработчика (УР) | человек-разработчик, в том числе John через месяц | из чего состоит экосистема, зачем каждая часть и как они связаны |
| Документация (`README.md`, `docs/` направлений, `contracts/`) | в первую очередь нейросеть, готовящая патч | что именно и как точно: версии, маршруты, форматы, команды |

Стены между ними нет: человек может открыть документацию, нейросеть — учебник.
Поэтому учебник ссылается на документацию за точными фактами, а документация
может сослаться на главу УР, когда нужно объяснить «зачем».

## 2. Чем учебник отличается от документации: путешествие

Документацию читают, чтобы **найти факт**: открыли нужное место, взяли ответ,
закрыли. Учебник читают, чтобы **пройти путь**: от «не понимаю, что это» до
«понимаю и могу сам». Отсюда правила:

- У книги есть маршрут. Главы идут по порядку, и каждая опирается только на
  предыдущие. В начале книги — карта маршрута: какие главы и что читатель
  сможет после каждой.
- Глава — один шаг пути. Она устроена так:
  1. **Вопрос**, который у читателя возникает именно здесь («почему телефон не
     видит ноутбук в другой сети?»).
  2. **История или пример**: случай, на котором вопрос виден.
  3. **Механизм**: как это устроено, без лишних подробностей. Нужна точная
     деталь — ссылка на документацию.
  4. **Попробуй сам**: что сделать или увидеть, чтобы убедиться (в УП — шаги
     в приложении, в УР — команда или файл).
  5. **Что дальше**: куда ведёт следующая глава.
- Если раздел превращается в справочную таблицу, ему место в документации, а
  в учебнике остаётся одна строка и ссылка.

## 3. Порядок: глоссарий → УР → УП

1. **Глоссарий** (`docs/textbooks/glossary.md`) — общий для обеих книг. Одна
   статья — один термин:
   - определение одной фразой;
   - объяснение для УП без жаргона, через бытовую аналогию;
   - где живёт точный факт (ссылка на документацию).

   Термин, которого нет в глоссарии, в учебнике не используется. Нужен новый —
   сначала статья в глоссарии, в том же патче.
2. **УР** (`docs/textbooks/developer/`) объясняет механизмы: узел, реплика,
   relay, capability, кольцо устройств, честные статусы, патчи и доска.
3. **УП** (`docs/textbooks/user/`) строится по УР, но для другого читателя:
   короткие фразы, ни одного термина без объяснения, слово «p2p» вводится
   через пример, а не определением. УП пишется после мета-бутстрапера, когда
   установка стала понятной для новичка.

## 4. Правила против устаревания

Главный риск учебника — стать ещё одним слоем документации и устареть, как
старые планы ([heritage.md](heritage.md)). Против этого:

- **Объясняет и ссылается, факты не копирует** (принцип 7). Номера версий,
  порты, маршруты, имена полей, числа из бюджетов в учебник не переписываются:
  вместо них ссылка на документ, где факт живёт.
- **Под заголовком каждой главы** — строка `Сверено: 2026-10-16, <коммит>`:
  когда глава последний раз проверялась против кода. По этой дате
  `docs_audit.py` видит главы, которые давно не перечитывались.
- **Ссылки и картинки проверяет страж**
  `python -B tools/ecosystem/check_textbooks.py` (раздел 6). Он входит в
  проверки каждого патча, который трогает `docs/textbooks/`.
- **Патч направления, который меняет механизм**, описанный в главе УР,
  кладёт на доску карточку «перечитать главу …», если сам главу не правит.

## 5. Картинки

Учебник с картинками понятнее, но растровые файлы засоряют историю git:
каждая версия PNG остаётся в ней навсегда. Поэтому картинка хранится **как
исходник**, а растра в git нет вовсе.

| Что | Чем | Где хранится |
|---|---|---|
| Схема (блоки, стрелки, последовательности) | Mermaid прямо в Markdown или SVG | в репозитории, `docs/textbooks/figures/*.svg` или блок ```` ```mermaid ```` |
| Рисунок «от руки» (что такое p2p, кольцо устройств как картинка) | [Excalidraw](https://excalidraw.com): SVG со встроенной сценой | в репозитории, `docs/textbooks/figures/*.excalidraw.svg` |
| Скриншот приложения | сценарий съёмки + PNG в GitHub Release издания | в репозитории только `docs/textbooks/shots.json`, PNG — ассеты релиза |

**Excalidraw** — бесплатная доска для рисования в браузере: прямоугольники,
стрелки и подписи в стиле «нарисовано от руки». При экспорте в SVG надо
включить «Embed scene»: тогда файл можно снова открыть на excalidraw.com
(File → Open) и продолжить править. Файл текстовый, весит десятки килобайт,
его может нарисовать и нейросеть, и человек. Растровые картинки внутрь SVG
не вставляются (страж это ловит).

**Скриншоты** не хранятся, а снимаются. В `shots.json` для каждого скриншота
записано, что снимать: направление, сценарий, тема интерфейса, размер окна,
имя файла. Снимки делает команда на хосте и выкладывает их ассетами GitHub
Release издания учебника (раздел 7). Учебник ссылается на ассет прямой
ссылкой, GitHub показывает её в тексте как обычную картинку. Читателю ничего
собирать не нужно; пересъёмка нужна только тому, кто выпускает новое
издание, когда интерфейс поменялся.

Фото и другие рисованные растровые картинки не используются. Google Drive
для учебников не используется: всё, что нужно для чтения, лежит в репозитории
или в его релизах, без коннекторов и входа в Google.

## 6. Страж

`python -B tools/ecosystem/check_textbooks.py` падает, если в
`docs/textbooks/`:

- лежит растровый файл (`.png`, `.jpg`, `.jpeg`, `.gif`, `.webp`, `.bmp`);
- в SVG встроен растр (`<image>` с `data:` или внешней ссылкой);
- SVG тяжелее 300 КиБ;
- относительная ссылка ведёт в несуществующий файл;
- картинка в Markdown ссылается на что-то, кроме файла из репозитория или
  ассета релиза учебника;
- ассет релиза упомянут в тексте, но не описан в `shots.json`, или описан, но
  нигде не используется.

Только стандартная библиотека, ничего не пишет, сеть не трогает.

## 7. Издание

Издание — снимок учебников, к которому приложены скриншоты: GitHub Release с
тегом `textbook-ГГГГ-ММ` (например, `textbook-2026-11`). Новое издание
выпускается, когда поменялись экраны, которые снимает `shots.json`. Ссылки на
скриншоты в тексте содержат тег издания, поэтому старое издание продолжает
показывать свои снимки.

Съёмку скриншотов по `shots.json` пока делать нечем: UIX-раннер web
(`web/tools/uiux/`) кликает и проверяет, но экраны не снимает. Шаг
`screenshot` для него — отдельная карточка web на доске. До неё в учебниках
используются схемы и рисунки, скриншотов нет.
