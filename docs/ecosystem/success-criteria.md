# Признаки удачного воркспейса

Воркспейс удачен, если он уменьшает стоимость координации и не увеличивает
стоимость работы внутри направления. Ниже — проверяемые признаки. Первые
проверяются автоматически уже сейчас, остальные — вручную или станут проверками
на следующих ступенях [пути интеграции](integration-path.md).

## Автономность

- Каждое направление собирается и проходит свои проверки из своего каталога
  без остальных (`git sparse-checkout set <направление>`).
- Ни один файл направления не ссылается на соседний каталог.
- Удаление корневого слоя не ломает ни одно направление.

## Координация

- `board/board.json` изменён в каждом коммите после инициирующего
  (проверяется `git log --format=%H -- board/board.json` против `git log`).
- У каждого изменения контракта есть карточки для всех потребителей.
- Порядок обновления (web-узлы → mobile → abl) записан в каждом патче, который
  трогает контракт.
- Нейросеть, получив один `devctl zip`, отвечает, куда движется вся экосистема,
  не спрашивая про соседние проекты.

## Честность

- Нет карточек в «Сделано», которые требуют проверки на хосте и её не прошли.
- Дрейф между направлениями измеряется, а не обнаруживается случайно.
- Метадокументация не пересказывает направления: при правке README направления
  корневые документы не приходится обновлять.

## Пользователь

- Для конечного пользователя ничего не сломалось: работающий web-узел, APK и
  Arch-пакет ведут себя как раньше.
- Взять только нужное направление можно одной понятной командой.

## Тревожные признаки

- корень начинает требовать инструменты (Node, Cargo, Docker), которых нет
  у направления;
- одна и та же правка регулярно приходит сразу в три направления — значит,
  контракт нужно вынести на ступень 1;
- доска обновляется формально: растёт `boardRevision`, но карточки не
  двигаются;
- патчи на несколько направлений становятся нормой, а не исключением.
