# E-ADR-001: общий слой документации и HTTP API узла как контракт

- Статус: **принято** John 2026-10-16, включая поправку к принципу 3
- Дата: 2026-10-16
- Повод: заметка John «сделать OpenAPI общим для проектов и вообще все
  документационные вещи, касающиеся всех тематических проектов» (devctl не
  берём: его дом — devctl-universal, здесь гостевая копия)

## Контекст

Документации в монорепозитории 1,8 МиБ Markdown в 277 файлах (аудит
`tools/ecosystem/docs_audit.py`, 2026-10-16): web 176 файлов и 1,1 МиБ, abl
58, mobile 14, devctl 10, корень 19. Общего между направлениями в ней три
вида, и лежат они по-разному:

| Что | Где сейчас | Беда |
|---|---|---|
| Контракты на проводе (кольцо, связка, встреча, отчёт об ошибке) | `contracts/` со схемами и векторами | нет: так и задумано |
| Старые контракты (`roaming/1`, `sync/1`, `device-link/2`, `web-node-link/1`, `p2p_planner_bundle`) | внутри web, копии фикстур в abl | карточка «Вынести контракты в contracts/» |
| **HTTP API узла** (`web/docs/api/openapi.yaml`, 6 186 строк) | внутри web | см. ниже |
| Термины и концепции (узел, реплика, relay, capability, кольцо, «Ждёт хоста») | рассыпаны по ADR и архитектурным документам | нет глоссария; каждый читатель собирает заново |

HTTP API узла — самый большой общий контракт, и он единственный без внешнего
потребителя в проверках:

- производит его web backend; читают **три** клиента: web UI, Android
  (`mobile/src`, несколько десятков маршрутов) и abl, чей frontend говорит
  теми же путями, а `src/shared/transport/desktop.ts` переводит их в команды
  Tauri;
- `web/tools/contract_parity_sweep.py` сверяет OpenAPI только с backend и
  web UI. На коммите 6cef464 он красный: 8 маршрутов узла нет в OpenAPI
  (в том числе `POST /auth/device-link/prepare`, которым пользуется Android),
  1 маршрут описан, но не смонтирован (`POST /auth/device-link/lan/inbox`),
  `info.version` = `0.2.0` при web `2.1.0`;
- Android и abl в сверке не участвуют вовсе.

## Решение

1. **Общее = то, что читает больше одного направления.** Это контракты,
   глоссарий, учебники (если будут, см. карточку «Два учебника») и наследие
   ([heritage.md](../heritage.md)). Всё это живёт в корне: `contracts/` и
   `docs/ecosystem/`. Остальное остаётся в направлениях, корень его не
   пересказывает (принцип 7).

2. **HTTP API узла становится контрактом `p2p-kanban-node-api/1`** в
   `contracts/node-api/1/openapi.yaml`. Владелец и единственный, кто его
   меняет, по-прежнему web: OpenAPI правится в том же web-патче, что и
   маршрут. Корневая проверка сверяет пути, которые вызывают mobile и abl,
   с этим файлом, так что Android, вызывающий несуществующий маршрут, падает
   в проверке, а не в поездке. Порядок обновления прежний: web-узлы → mobile
   → abl.

3. **Поправка к принципу 3** ([principles.md](../principles.md), внесена). Было «направления корень не читают», а тесты mobile уже читают
   `contracts/error-report/1/vectors/*.json` из корня, и
   [contracts/README.md](../../../contracts/README.md) это разрешает. Предлагаемая
   формулировка: *сборка и запуск направления корня не читают; его проверки
   могут читать `contracts/` (или копию, сделанную при сборке).* Без этой
   поправки п. 2 нарушает принцип, с ней — узаконивает то, что уже есть.

4. **devctl в общий слой не входит.** Его документация живёт в
   devctl-universal; в `docs/ecosystem/devctl.md` только то, как экосистема
   им пользуется.

## Порядок перехода

| Шаг | Патч | Что |
|---|---|---|
| 1 | web | OpenAPI догоняет узел: 8 маршрутов, удалить призрачный, версия; `contract_parity_sweep.py --check` зелёный |
| 2 | экосистема + web (контракт назван) | перенос в `contracts/node-api/1/`, запись в `compatibility.json`, web-проверки читают новый путь; поправка принципа 3 |
| 3 | экосистема | корневая проверка путей mobile и abl против OpenAPI |

Шаг 1 полезен при любом исходе этого ADR.

## Отвергнуто

- **Оставить OpenAPI в web и сверять клиентов из корня.** Работает, но
  контракт трёх направлений остаётся внутри одного; при выделении
  направления в отдельный репозиторий его клиенты теряют источник.
- **Общий сгенерированный клиент для всех трёх.** Это общий код
  (принцип 2: только после трёх расходящихся реализаций); abl говорит через
  IPC, а не через HTTP.

## Связь с мета-бутстрапером

Мета-бутстрапер выбирает направления по профилю. Если контракты, глоссарий и
наследие лежат в корне, установка «только abl» всё равно получает всё, что
нужно, чтобы понять, с чем abl совместим.
