# A15 — PKGBUILD + signed repository packaging

## Status

Implemented at source/deterministic/release-preparation level. Canonical Arch host packaging UTS and the manual clean-chroot/install/signing matrix are the acceptance gates.

## Package ownership boundary

A15 makes pacman the only owner of installed application files. The package installs only:

- `/usr/bin/p2pkanban`;
- `/usr/share/applications/org.p2pkanban.archnative.desktop`;
- `/usr/share/icons/hicolor/64x64/apps/p2pkanban.png`;
- `/usr/share/licenses/p2pkanban/LICENSE`.

There is no package install/remove scriptlet, root helper, systemd unit, database initialization, keyring mutation or user-profile deletion. Runtime data remains under the existing A06 XDG profile roots and therefore survives `pacman -R` by design.

The application does not execute `pacman`, `sudo`, `pkexec`, `makepkg` or repository tooling. A package update is an external package-manager operation; A15 does not add a self-updater or partial-upgrade path.

## Release source and dependency binding

`packaging/arch/PKGBUILD` is a readable bootstrap recipe. Its source checksum marker is deliberately invalid for publication. `tools/a15_prepare_release.py` is the only supported transition from repository source to release inputs:

1. require the exact `Cargo.lock` already accepted/generated by canonical UTS;
2. assemble an explicit build-input set (frontend, native source, migrations, icons and protocol/import fixtures);
3. inject that lock into a deterministic `p2pkanban-<version>.tar.gz` with normalized metadata;
4. hash the archive and replace the PKGBUILD marker in a staging copy;
5. retain package-lock, Cargo.lock, migration-set and fixture-set digests in `release-inputs.json`.

The resulting PKGBUILD has no `SKIP`. `prepare()` may download/cache npm and Rust dependencies, but Cargo uses `--locked`; `build()` and `check()` use `--frozen`. No dependency is resolved from a floating application source during the actual build/check phases.

The source repository still does not own a committed `src-tauri/Cargo.lock`; A15 binds the canonical UTS lock into each retained release source archive instead. This is explicit debt, not a reproducibility claim about arbitrary Git checkouts.

## Desktop/deep-link registration

The package owns `org.p2pkanban.archnative.desktop` and registers `x-scheme-handler/p2pkanban` with `Exec=p2pkanban %u`. A13 already bounds and validates incoming `p2pkanban://` argv values before they enter the single-instance activation channel, so A15 does not add shell interpolation or a second deep-link parser.

Portable bundle MIME registration remains deferred: A11 import is still a native application operation without a package-level file-open contract.

## Signed repository boundary

`tools/a15_stage_signed_repo.py` accepts only a built `p2pkanban-...-x86_64.pkg.tar.zst`, an external hexadecimal GPG key id/fingerprint and an output directory. It:

- signs the package through the caller's configured GPG agent/keyring;
- verifies that detached signature;
- runs `repo-add --prevent-downgrade --include-sigs --sign --key ...`;
- verifies the repository database signature;
- writes a hash/size/key-fingerprint release manifest.

The tool has no option for a private-key file or passphrase and never exports secret key material. `packaging/arch/pacman-repo.conf.example` requires signatures with `TrustedOnly` and documents two HTTPS mirror slots; example origins are intentionally non-routable until the release operator substitutes project-controlled mirrors.

## Host acceptance

Canonical UTS runs `tools/a15_host_packaging_probe.py` after the normal native build. The probe is non-root and does not install packages or alter pacman configuration. It binds the UTS Cargo.lock into release inputs and requires:

- `makepkg --printsrcinfo` and `--verifysource`;
- `namcap PKGBUILD`;
- `desktop-file-validate`;
- availability of `makechrootpkg`, `repo-add` and `gpg`;
- exact archive checksum and retained Cargo/npm/migration/protocol hashes;
- no generated workspace state or private-key-shaped files in the release stage.

CORR-A15-001 hardens the non-root host preflight after real Arch devtools evidence: `makechrootpkg` is probed with its supported short `-h` option, and `namcap PKGBUILD` output is fail-closed on `E:` diagnostics. The bootstrap PKGBUILD now carries a deliberately non-routable `https://example.invalid/p2pkanban` project URL so internal package lint is structurally complete without inventing a public project origin; release publication must replace that placeholder together with the example repository mirrors.

Final release evidence remains intentionally external/manual because it changes host package state or needs the real release key: clean-chroot build, `namcap` on the produced package, signed repository publication/verification, pacman install/upgrade/`-Qkk`, and uninstall preserving XDG/keyring data.

## Explicit non-claims

A15 is not AppImage packaging (A17), backup/recovery (A16), an automatic updater, an AUR publication, or a public-license decision. The repository currently carries an explicit packaging notice rather than inventing redistribution rights; public AUR/mirror publication is blocked until the owner supplies a software license.

CORR-A15-002 records the follow-up target-host finding that `makechrootpkg -h` emits its valid Arch devtools help text while returning a non-zero status. The host probe therefore keeps executable presence in the PATH gate and validates the `-h` output by its `Usage: makechrootpkg` and `Flags:` markers without requiring exit code zero. This changes only non-root packaging preflight semantics.
