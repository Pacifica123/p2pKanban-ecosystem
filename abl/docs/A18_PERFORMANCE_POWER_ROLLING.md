# A18 — производительность, энергопотребление, rolling-release

A18 превращает три требования дорожной карты (бюджеты измерены, канарейка перехода
WebKitGTK, хаос suspend/сети) в инструменты, которые сам UTS запускает на хосте.
Код приложения, схема (v6), протоколы и CSP не меняются. Ничего не ставится, не
усыпляет хост и не трогает сеть или firewall: только чтение `/proc`, запросы
`pacman -Q`/`pkg-config`/`ldd` и запуск уже собранного бинарника в изолированных
XDG-каталогах.

## Что запускает UTS

| Шаг UTS | Инструмент | Что доказывает |
|---|---|---|
| `host.a18-rolling-canary` | `tools/a18_rolling_canary.py check --in-uts` | бинарник и помощники WebKit загружаются; какая линия WebKitGTK/GTK/glib/glibc/OpenSSL сейчас стоит и чем она отличается от последнего зелёного UTS |
| `host.a18-profile-scale` | `tools/a18_host_budget_probe.py profile-scale` | профиль на 10 000 карточек и 100 000 ожидающих изменений: размер, время `doctor` и `backup` реального бинарника |
| `runtime.a18-runtime-budgets` | `tools/a18_host_budget_probe.py runtime` | запуск, память, CPU и пробуждения в простое, диск, тишина сети, чистый выход; пустой профиль и профиль-фикстура |
| `runtime.a18-chaos` | `tools/a18_host_chaos_probe.py` | freeze-thaw, hard-kill, шторм вторых экземпляров, пропавшая сессионная шина, старт без сети |

`--no-runtime` пропускает оба шага `runtime.*` вместе с `runtime.launch-probe`.
Отчёты JSON лежат в каталоге прогона UTS рядом с логами, логи самого приложения в
`a18-app-logs/`.

## Бюджеты

Пороги лежат в `packaging/budgets/a18-budgets.json`. Сейчас их статус **proposed**:
это стартовая оценка для ноутбука x86_64 с 8–16 ГиБ (EX-ARCH-001), а не измерение.
Пока статус proposed, превышение числового бюджета печатается и записывается в
отчёт, но шаг UTS не краснеет. Два инварианта красят шаг всегда:

- в простое у дерева процессов нет ни одного TCP/UDP-сокета (`idleInetSockets = 0`);
- через 5 секунд после SIGTERM главному процессу не живёт ни один процесс дерева
  (`processesAfterExit = 0`): никакого невидимого фонового демона.

Порядок принятия:

1. UTS собирает debug, поэтому его числа только ориентир: пороги для debug
   умножаются на `debugAllowance` (время ×4, CPU ×3, память ×1.5).
2. Измерение для Gate G — release на эталонном ноутбуке, от сети и от батареи:

   ```bash
   cargo build --release --locked --offline --manifest-path src-tauri/Cargo.toml
   python3 -B tools/a18_host_budget_probe.py all --profile release --report /tmp/a18/a18-release-budgets.json
   ```

3. По этому отчёту пороги калибруются, статус становится **accepted**, и с этого
   момента любое превышение красит UTS. Превышение, с которым решено жить, вносится в
   `acceptedDeviations` только со ссылкой на ADR.

### Как измеряется и где это прокси

- **Запуск** — от spawn до момента, когда CPU всего дерева держится ниже 5% одного
  ядра 0.5 с после появления процесса WebKitWebProcess. Это прокси «окно готово»:
  приложение не сообщает о готовности само, а менять Rust ради метрики A18 не стал.
- **CPU** — utime+stime из `/proc/<pid>/stat` по всем процессам дерева за окно простоя
  (по умолчанию 30 с).
- **Пробуждения** — сумма переключений контекста всех потоков в секунду. Это прокси
  для powertop-wakeups: он завышает, но не занижает.
- **Память** — сумма Pss из `smaps_rollup` (общие библиотеки WebKit делятся честно,
  а не считаются трижды). Rss записывается рядом.
- **Диск** — размер XDG-каталогов после простоя; размер профиля и резервной копии
  фикстуры.

Фикстура засевается через те же SQL-миграции и контрольные суммы, что и в A16;
реальный бинарник принимает её `doctor` как здоровый профиль v6.

## Канарейка rolling-release

```bash
python3 -B tools/a18_rolling_canary.py check      # после каждого pacman -Syu
python3 -B tools/a18_rolling_canary.py snapshot   # просто показать отпечаток
```

Отпечаток: версии `webkit2gtk-4.1`, `gtk3`, `glib2`, `libsoup3`, `openssl`, `glibc`
(через `pacman -Q`, на не-Arch через `pkg-config`), полный список so-имён из `ldd`,
наличие `WebKitWebProcess`/`WebKitNetworkProcess` и их загружаемость.

| Вердикт | Код выхода | Что делать |
|---|---|---|
| `ok` | 0 | система та же, на которой прошёл последний зелёный UTS |
| `uts` | 3 | дрейф patch/pkgrel: перезапустить UTS |
| `rebuild-and-uts` | 3 | сменилась minor/major-линия или набор so-имён: пересобрать и перезапустить UTS |
| `broken` | 1 | не грузится библиотека или помощник WebKit: приложение и его `doctor` не стартуют |

При `broken` канарейка печатает диагноз и ничего не чинит: закончить обновление
полным `pacman -Syu` (не копировать библиотеки и не откатывать отдельные пакеты),
пересобрать, перезапустить UTS; профиль не тронут, а до пересборки планировщик
доступен через офлайн-комплект A17.

Базовая линия ведётся сама. Внутри UTS канарейка сохраняет текущий отпечаток как
кандидата, привязанного к каталогу прогона. Следующий `check` делает кандидата
базовой линией, только если `results.json` этого прогона говорит `overall: pass`;
упавший или прерванный прогон кандидата выбрасывает. Файлы лежат вне дерева
проекта, в `~/.local/state/p2pkanban-dev/` (`a18-rolling-baseline.json` и журнал
переходов `a18-rolling-history.jsonl`), поэтому базовую линию видит и UTS из
свежей копии UserTestSpace, и общий тестер экосистемы. Профиль приложения
(`~/.local/state/p2pkanban/`) канарейка не трогает. Внутри UTS вердикты `uts` и
`rebuild-and-uts` не красят шаг: этот прогон и есть пересборка и перепроверка.

## Хаос

| Сценарий | Что делает | Условие прохождения |
|---|---|---|
| freeze-thaw | SIGSTOP всему дереву на 20 с, затем SIGCONT: так приложение видит suspend | живо, за 10 с после разморозки CPU ≤ 10% ядра, нет inet-сокетов, чистый выход, `doctor` здоров, 10 000 карточек на месте |
| hard-kill | SIGKILL всему дереву (пропало питание, OOM) | `doctor` без safe mode, карточки на месте, приложение снова запускается |
| instance-storm | 8 вторых экземпляров разом при работающем первом | все вышли с кодом 0, первый жив, лишнего web view не открылось |
| bus-gone | адрес сессионной D-Bus указывает в пустоту | деградированный старт без падения, чистый выход |
| offline-netns | старт в новом сетевом пространстве через `unshare --user --map-current-user --net` | старт без сети, нет inet-сокетов; если ядро или util-linux не разрешают — `unavailable`, а не pass |

Здесь не доказывается и вынесено в ручную проверку: настоящий `systemctl suspend`
с открытым окном и правкой до сна; прыжок системных часов (нужны привилегии);
переподключение к relay после сна — оркестрации relay ещё нет (A10).

## Что A18 не утверждает

- Числа из облака (Xvfb, программная отрисовка) не являются доказательством бюджета;
  доказательство — release-прогон на эталонном Arch-ноутбуке.
- Бюджеты остаются proposed до этого прогона; Gate G требует accepted.
- Поддержка конкретных версий WebKitGTK/Arch-производных (OQ-ARCH-002/010) по-прежнему
  открыта: канарейка копит журнал переходов, из которого эта матрица потом строится.
