# «Скопировать подробности» в abl

Контракт: [error-report/1](../../contracts/error-report/1/SPEC.md). Патч `2026-10-07-abl-error-details`.

## Что видит пользователь

Под красной полосой ошибки в окне abl есть кнопка «Скопировать подробности».
Она кладёт в буфер обмена текст отчёта: сначала для человека (программа,
платформа, где, сообщение, последний неудачный вызов), в конце канонический
JSON `p2p-kanban-error-report/1`. Если буфер обмена WebView недоступен, текст
показывается в поле, откуда его можно скопировать вручную.

## Откуда данные

- `software`: `abl <version из package.json>`, сборка из `P2PKANBAN_BUILD`
  (если задана при `vite build`), коммит из `P2PKANBAN_SOURCE_REVISION` или
  `git rev-parse HEAD` в момент сборки. В пакете PKGBUILD сборка пока не
  задаётся (доказательства A15 закреплены по digest), поэтому там
  «сборка неизвестна».
- Ошибки нативных команд Tauri (строки) превращаются в `ApiError` с кодом
  `NATIVE_ERROR` и видом `native`; запрос и ответ попадают в журнал.
- Журнал: последние 200 строк в памяти WebView (console.warn/error,
  необработанные ошибки и отказы промисов, неудачные вызовы); в отчёт идут
  50, после вычистки секретов. На диск ничего не пишется, по сети ничего
  не отправляется.
- `peer` пока `null`: abl не ходит к web-узлу по HTTP.

## Проверка

- `node tools/check_error_report.mjs` — `report.ts` против векторов
  `contracts/error-report/1/vectors`;
- `npm run typecheck`, `npm run build`;
- на хосте: вызвать любую ошибку (например, открыть недоступный профиль),
  нажать «Скопировать подробности», вставить в редактор: в первой строке
  «Программа: abl … · коммит …», в конце JSON.
