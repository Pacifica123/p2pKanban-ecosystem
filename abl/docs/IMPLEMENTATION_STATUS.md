## Explicit non-claims after A02d

Post-A02b UTS evidence now shows a complete frontend build, resolver lock/fetch, `cargo test --locked --offline`, `cargo build --locked --offline`, binary presence, and non-root Wayland runtime launch probe passing on Manjaro. The runtime evidence recorded no TCP listener owned by the application process tree. The second immediate UTS invocation exposed three repeatability bugs in deterministic checkers; A02c fixed those checker defects and added a post-build deterministic replay. The next fresh UTS snapshot then proved that devctl UserTestSpace intentionally omits `.git`; A02d corrects the repository-view helper so deterministic gates work in both Git workspaces and Git-less UTS snapshots without hiding secret/runtime payloads.

This still does **not** claim manual rendered WebView health text or hostile-navigation runtime behavior has been observed. `src-tauri/Cargo.lock` generated in UTS is also not silently incorporated because its exact bytes were not supplied as a source artifact. A03 now provides the application/domain service boundary behind Tauri IPC. A04 implements the storage-independent repository semantic contract and executable in-memory reference suite. Its first UTS `cargo test` exposed a generic-helper compile defect; A04b corrected that defect without changing semantics and the subsequent UTS run is green. A05 now adds the first embedded SQLite profile schema/migration/repository adapter behind that contract. A06 now adds the final XDG profile layout and kernel-owned single-writer instance control; runtime activation remains capability-detected and does not weaken writer exclusion when `$XDG_RUNTIME_DIR` is absent. A07 adds a session-only secret-vault boundary and the first durable workspace/board UI workflow; A07b corrected its first UTS compile defects and the user-reported rerun is green. A08 now extends the same native path with durable columns, cards, archive/move/delete, checklist basics, tombstones and payload-free local pending markers. A08 does not claim remote convergence. A09 now implements production secret persistence at the provider/storage boundary, while the full GNOME/KWallet/minimal-session matrix remains experiment-needed. A10 now adds the local sync-core/roaming compatibility layer and durable protocol outbox, but still does not claim relay orchestration or multi-node convergence. There is still no Nostr coordinator, Linux package or selectable multi-profile UX.


## A09 explicit non-claims

A09 protects typed credentials/capabilities/keys, not planner content. It does **not** claim SQLCipher/full-database encryption, automatic keyring daemon/PAM setup, provider migration UX, multi-host GNOME/KWallet proof, remote login/device-link provisioning, or sync/P2P behavior. When no usable durable provider is available, planner data remains readable but durable secret operations stay fail-closed/session-only.

## A09b UTS correction

Canonical A09 UTS proved the application/frontend gates but rejected the dependency graph during final offline lock resolution because `chacha20poly1305 0.11.0` selected yanked `chacha20 0.10.1`. A09b changes only that AEAD pin to the stable 0.10.1 line; offline acceptance remains mandatory.


## A11 boundary note

A11 adds a Rust-only destination/import boundary for device-link/2, web-node-link v1 and portable bundle v1. It does not expose generic file/keyring/network privileges to the WebView and does not claim live relay signature/chunk transport or legacy-node HTTP/session orchestration. SQLite import is transactional and migration-targeted imports require an empty/fresh profile while preserving stable logical UUIDs; board/device secret material remains SecretVault-only, with collision rejection and best-effort compensation across the unavoidable SQLite↔Secret Service transaction boundary.
The first A11 host UTS passed deterministic/frontend checks and exposed a Cargo verifier ordering defect: network lock generation happened before the selected crates were fetched, so the immediate offline re-resolve depended on historical host cache contents. The verifier correction then reached real Rust compilation. Host UTS `20260915T073257Z` exposed only source-level compile regressions: ambiguous `serde_json::Map::entry("...".into())` keys under the resolved graph and an A09 `VaultStatus` test initializer that predated the `state`/`passphrase_fallback_available` fields. A11 corrects those source/test defects without changing import/link semantics; canonical Cargo/offline acceptance remains pending the next UTS rerun.
