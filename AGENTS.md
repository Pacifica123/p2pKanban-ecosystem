# Правила для нейросети, готовящей патч

1. Это монорепозиторий из четырёх самостоятельных направлений: `web/`,
   `mobile/`, `abl/`, `devctl/`. Внутри направления действуют его README и docs.
2. Изменения приходят только devctl-патчем (`devctl/docs/patch-format.md`),
   пути — от корня репозитория. Шаблон: `docs/ecosystem/patch-manifest.template.json`.
3. **Каждый патч обновляет `board/board.json`**: `boardRevision` + 1,
   `lastPatchId`, карточка сдвинута или создана, комментарий с `patchId`.
   Проверка `python -B tools/ecosystem/check_board.py --require-changed`
   обязательна в каждом манифесте.
4. Патч по умолчанию трогает одно направление. Если меняется контракт между
   направлениями, назови его и порядок обновления (web-узлы → mobile → abl).
5. Не связывай направления через `../` и не добавляй в корень зависимости,
   которых нет у направлений.
6. Не выдавай реализованное в исходниках за принятое на хосте: для этого
   колонка «Ждёт хоста».
7. Перед работой прочитай доску и `docs/ecosystem/README.md`.
8. Общие контракты лежат в `contracts/`. Векторы не правятся руками: правится
   `tools/ecosystem/contract_vectors.py`, затем
   `python -B tools/ecosystem/contract_ref.py generate`.
