# Разные сети: исправления от 1 октября 2026

Применять отдельные devctl-патчи к соответствующим проектам: web на ПК и ноутбуке,
Android к исходникам мобильного приложения. Данные и настройки устройства сохраняются.
Версия протокола и схема БД не меняются; сброс профиля или повторный импорт не требуется.

## Что исправлено

- Web: включён `reqwest/json`, обновлён связанный Cargo.lock. Это устраняет E0599
  в `auth/lan_link.rs`. Ошибки компиляции больше не повторяются как сетевой сбой,
  даже если выше в Docker-логе встречается TLS/registry.
- Web: отказ запуска roaming worker больше не отключает его до перезапуска процесса:
  повтор выполняется через 5 секунд. Запрос каталога ограничен получателем `#p`.
- Android: подготовленная доска читает relay без ожидания HTTP-адреса ПК. Это работает
  одинаково при мобильном интернете и чужом Wi-Fi; тип сети не доказывает доступность ПК.
- Android: каталог пространств/досок опрашивается независимо от успеха HTTP, каждые
  30 секунд на открытом экране. Доски, обнаруженные через relay, не скрываются старым
  непустым HTTP-списком. Каталог от введённого доверенного ноутбука принимается только
  после проверки введения и адресованного разрешения для текущего пользователя.
- Android: выбирается новейший проверенный каталог, старое поколение ключа не заменяет
  новое, изменение ключа без нового поколения отклоняется. Пустой/дублированный набор
  relay не создаёт ложного подтверждения публикации. Чужие подписанные события вне
  фильтра доски/получателя отклоняются.

## Порядок обновления

1. Примените web-патч через `devctl start` в workspace web-проекта. Сделайте это
   для каждого собственного web-узла. Из каталога проекта запустите
   `python bootstrap.py start`: образы готовятся до замены работающего stack.
   При E0599/TOML/lockfile-ошибке не делайте reset: проверьте, что патч применён
   к исходникам той машины, где собирается образ.
2. Примените Android-патч через `devctl start` в его workspace. Соберите APK обычным
   `npm run apk` и установите поверх приложения. Не удаляйте данные приложения.
3. На доступном исходном узле подготовьте доски и разрешение подключения нового
   устройства, если это ещё не сделано. Уже действующие сохранённые разрешения
   не требуют обращения к ПК при каждом открытии доски.
4. Переключите Android на мобильный интернет или другую Wi-Fi-сеть. Проверьте
   открытие сохранённой доски, редактирование и повторное открытие. Изменение сначала
   сохраняется локально. Подтверждение relay — приём журналом, а не гарантия, что
   каждый выключенный узел уже применил событие.

## Проверка на устройствах после патча

- ПК и ноутбук подключены к разным сетям: созданная/изменённая карточка доходит
  через общие доступные relay. Android при этом не является HTTP-прокси.
- ПК выключен: на подготовленном Android изменения сохраняются, очередь переживает
  закрытие приложения; после восстановления relay/узла доходит то же событие.
- В уже доверенном пространстве появляется новая доска: на открытом экране каталог
  обновляется за очередной успешный цикл. Базовый снимок тоже должен быть опубликован.
- Один relay недоступен: результат зависит от настроенного числа обязательных ACK;
  оно не понижается автоматически. Пока кворума нет, запись остаётся pending.
- HTTP недоступен, relay доступны: сохранённые доски и каталоги работают автономно.
  Если capability отсутствует, первоначальную подготовку нужно выполнить у доступного
  доверенного узла. Закрытый LAN-адрес не становится публичным из-за наличия relay.

## Что доказано и что требует host-проверки

Проверки типов/Jest Android, backend Cargo locked compilation/unit tests,
web build/unit tests и Python bootstrap regressions запускаются при подготовке патчей.
Дополнительно используйте `npm run typecheck`, `npm test` и `npm run export:android`
в Android-проекте; `cargo test --manifest-path backend/Cargo.toml --locked --lib`
и `python3 tools/check_production_images.py` в web-проекте.

Проверки devctl в этих патчах не скачивают зависимости: это быстрые offline contract
и bootstrap checks. Они не заменяют перечисленные сборки. Настоящий Docker daemon,
APK на смартфоне, физические сети/ISP/VPN и PostgreSQL-интеграция должны быть проверены
на устройствах. Отсутствие свежих исходных runtime-логов не позволяет считать всю
сетевую проблему воспроизведённой одним совпадающим build-логом.

ABL A17 относится к упаковке/восстановлению, а не к добавлению живого relay-адаптера:
его A10/A11 ограничения транспортной оркестрации остаются.
