# Интерфейс не ждёт синхронизацию: исправление от 6 октября 2026

Симптом: зашёл в доску, и выйти в меню нельзя, пока «что-то внутри не
досчитается». Кнопки не реагируют, системная «Назад» тоже. Хуже всего в
плохой сети и на досках с длинной историей.

## Почему прошлое исправление не удержалось

Прошлое исправление (`boardExit.ts`, `InteractionManager.runAfterInteractions`)
сделало выход синхронным и отложило первую синхронизацию до конца анимации
открытия. Оба шага верные, но они лечили **ожидание**, а не **занятость**.
В React Native нажатия, «Назад» и `navigation.pop()` обрабатываются тем же
JS-потоком, что и синхронизация. Если поток занят, мгновенный выход тоже ждёт.

Поток был занят работой, которая растёт вместе с историей доски и повторяется
каждые 15 секунд:

| Что происходило | Почему растёт | Чем грозит |
|---|---|---|
| каждый опрос relay запрашивал **всю** историю тега доски | relay не получали курсора `since` | весь журнал по сети каждые 15 с |
| подпись Schnorr каждого события проверялась прямо в `onmessage` | для каждого relay отдельно, для уже известных событий тоже | на Hermes это десятки миллисекунд на событие; сотни событий × 2 relay = секунды без ответа на нажатия |
| каждое событие заново расшифровывалось, цепочки делегирования заново проверялись | без учёта уже принятых | ещё столько же синхронной работы |
| после каждого опроса весь журнал переигрывался (`projectJournal`) и записывался целиком | даже если ничего нового не пришло | разбор и запись многомегабайтного JSON |
| `useEffect` запускал `flush` на **каждое** изменение массива операций, а `flush` сам его меняет | без relay очередь не пустеет | бесконечный цикл тяжёлых попыток при плохой сети |
| экраны пространств и досок под открытой доской продолжали опрашивать каталог каждые 30 с | native-stack держит их смонтированными | ещё одна конкурирующая проверка подписей |
| смена типа сети пересоздавала `refresh/flush` и заново «открывала» доску | эффект гидратации зависел от них | доска снова показывала «Открываем доску» |
| HTTP-запросы к узлу выполнялись под общей блокировкой локального хранилища | — | правка карточки ждала таймаута узла (12 с на запрос) |

Поэтому проблема «возвращалась»: после прошлого патча история была короткой,
и всё работало; по мере роста журнала время одного опроса снова превысило
терпение пользователя. Код выхода при этом не менялся.

## Что изменено

1. **Известное не проверяется заново.** Журнал хранит `wireIds` (принятые
   события relay) и `rejectedWireIds` (невалидные навсегда в этом поколении
   доступа). Идентификатор события Nostr — хеш его содержимого, поэтому
   совпадение id означает то же содержимое. Свои подписанные события тоже
   считаются известными.
2. **Проверка подписей вынесена из `onmessage`.** Кадры сначала собираются,
   дубликаты между relay сливаются, известные отбрасываются, остальное
   проверяется по одному на событие порциями по 8 мс с возвратом потока
   интерфейсу (`shared/lib/uiBudget.ts`). Поддельная копия под чужим id не
   скрывает настоящую с другого relay.
3. **Инкрементальный опрос.** Плановый опрос просит у relay только события
   после курсора (с перекрытием в час на расхождение часов). Полный опрос —
   при открытии доски, возврате приложения, ручном «Обновить» и не реже раза
   в 10 минут: так приходят изменения, подписанные офлайн давно и
   опубликованные поздно.
4. **Без нового — без переигрывания.** Журнал записывается и
   переигрывается только когда пришло новое событие. Курсор опроса хранится
   отдельной маленькой записью.
5. **Доска открывается из сохранённой копии сразу.** Восстановление журнала
   после сбоя идёт уже после показа доски; сеть не стоит между пользователем и
   доской. Смена Wi-Fi/мобильной сети больше не переоткрывает доску.
6. **Уход с экрана останавливает работу.** У открытой доски свой
   `AbortController`; закрытие экрана прерывает синхронизацию между шагами.
   Пока поверх доски открыт другой экран, периодический опрос на паузе.
   Экраны пространств и досок опрашивают каталог только когда видны.
7. **Без бесконечного цикла.** `flush` запускается при появлении новой
   локальной операции, а не на каждое изменение массива. После неудачи
   повторы идут с нарастающей паузой: 15 с, 30 с, … до 5 минут. Ручные
   действия сбрасывают паузу.
8. **Сеть никогда не держит блокировку хранилища.** Запрос к узлу выполняется
   вне `serializeLocalState`, результат применяется к актуальному состоянию
   короткой локальной транзакцией. Окно оформления и окно колонки закрываются,
   не дожидаясь сети.

## Инварианты (проверяются `npm run check:contract` и Jest)

- выход из доски не зависит от синхронизации (`boardExit`, без изменений);
- проверка подписей relay — один раз на новое событие и порциями;
- опрос без новых событий не переигрывает и не перезаписывает журнал;
- `useLocalBoard` не использует `InteractionManager`, гидратация не ждёт сети;
- закрытый экран останавливает синхронизацию.

## Что осталось долгом

- Журнал не компактизируется. Первое переигрывание после появления нового
  события всё ещё синхронное и растёт с историей. Компакция журнала и
  chunked baseline — отдельная карточка на доске экосистемы. Там же риск:
  Android `AsyncStorage` не читает одну запись больше ~2 МБ.
- Множества `wireIds` растут вместе с журналом и будут сжаты той же компакцией.
- Первый опрос после обновления приложения один раз проверит всю историю
  (известных id ещё нет), но уже порциями, не блокируя интерфейс.

## Приёмка на телефоне

Детерминированные проверки — `npm run typecheck`, `npm test`,
`npm run check:contract`, `npm run export:android` — не заменяют телефон.
На установленном поверх APK (versionCode 24, данные не очищать):

1. Открыть доску с длинной историей. Сразу нажать «Назад»: выход мгновенный.
2. Включить авиарежим при открытой доске, подождать минуту, войти и выйти из
   доски несколько раз, открыть карточку и закрыть её.
3. Переключить Wi-Fi ↔ мобильная сеть при открытой доске: доска не
   показывает «Открываем доску» заново.
4. Создать карточку без сети, вернуть сеть: карточка уходит без ручных действий.
5. Оставить доску открытой на 5 минут в нормальной сети, всё это время
   прокручивать колонки: нет подвисаний на 15-секундных опросах.
