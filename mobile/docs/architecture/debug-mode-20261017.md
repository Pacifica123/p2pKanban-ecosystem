# Режим отладки на телефоне

Патч `2026-10-17-mobile-debug-mode`, versionCode 28. Продолжение
[«Скопировать подробности»](error-details-20261007.md): тот же журнал в памяти,
но его можно смотреть в реальном времени, он подробнее и переживает перезапуск.

## Зачем

«Скопировать подробности» отдаёт 50 последних строк в момент ошибки. Этого мало,
когда ошибки нет, а поведение странное: после перехода с Wi-Fi на мобильную сеть
новые доски не появляются, на «Пространствах» «Офлайн-копия». Нужно видеть, что
приложение делало всё это время: какая сеть, подтвердил ли узел сессию, что
ответили relay, какая доска откуда взяла снимок.

## Что видит человек

Настройки → **«Режим отладки»**: переключатель и кнопка «Открыть журнал».
Экран «Журнал отладки»:

- строки появляются по мере работы, список сам прокручивается вниз; «Пауза»
  останавливает прокрутку и обновление;
- фильтр «Всё» / «Ошибки» (warn и error);
- «Прошлый запуск» — хвост журнала предыдущего запуска (если режим был включён):
  видно, чем кончилось, когда приложение зависло или его закрыла система;
- «Скопировать» кладёт журнал в буфер обмена в Markdown, «Сохранить .md» пишет
  файл `p2pkanban-mobile-debug-<время>.md` и открывает окно «Поделиться».

## Что меняет включённый режим

| | Выключен (как раньше) | Включён |
|---|---|---|
| строк в памяти | 200 | 5000 |
| что пишется | запросы к узлу (с временем ответа), warn/error, зависания JS-потока, смена сети, уход в фон, офлайн-сессия | плюс шаги синхронизации досок, отправка и чтение relay по каждому relay, смена экранов |
| на диске | ничего (кроме метки тяжёлой работы stallWatch) | последние 500 строк, уже без секретов, раз в 3 с |

Переключатель хранится на телефоне (`AsyncStorage`). Выключение стирает
сохранённый хвост. Подробные строки собираются только при включённом режиме
(`trace(source, () => текст)`), поэтому в обычной работе нагрузки нет.

## Источники строк

| Источник | Что |
|---|---|
| `net` | тип сети и есть ли подключение, одна строка на изменение |
| `app` | приложение на экране / в фоне |
| `auth` | сессия подтверждена узлом или открыта офлайн-копия и почему |
| `api` | каждый запрос к узлу: метод, путь, статус, миллисекунды |
| `board` | доска открыта (есть ли локальная копия и ключ relay), снимок с узла, чтение relay, изменение записано, узел или relay принял, ошибка синхронизации |
| `relay` | отправка и чтение: сколько relay ответили и что сказали остальные |
| `nav` | открытый экран |
| `ui`, `console`, `js`, `fatal` | как раньше: зависания, предупреждения, необработанные ошибки |

## Что не попадает в журнал

- Пароли, токены, JWT, `nsec`, ключи досок: каждая строка при показе, копировании
  и записи на диск проходит `redact` из [error-report/1](../../../contracts/error-report/1/SPEC.md).
- Тексты карточек, чек-листов и комментариев: строки `board` называют только id
  (первые 8 символов доски), вид операции и числа.

Журнал никуда не отправляется сам: только в буфер обмена или в «Поделиться» по
нажатию.

## Проверка

- `npx jest src/shared/debug` — ёмкость, ленивые строки, подписка, Markdown,
  вырезание секретов, имя файла;
- `node scripts/check-core-crud-contract.mjs` — versionCode 28 и наличие режима;
- на телефоне: включить режим → открыть доску → переключиться с Wi-Fi на
  мобильную сеть → открыть журнал: есть строки `net`, `auth`, `board`, `relay`;
  закрыть приложение из списка задач, открыть снова → «Прошлый запуск».
