# Зависание «ничего не нажимается» (2026-10-16)

Патч `2026-10-16-mobile-ui-freeze`, versionCode 26. Владелец — mobile, контракты не меняются.

## Что видел пользователь

Приложение переставало отвечать на нажатия и кнопку «Назад»; помогала только
выгрузка из недавних. Два сценария: «Получить запрос с ноутбука» и попытка
выйти; несколько минут без действий и возврат в приложение.

## Причина

Общий корень — работа, которая на минуты занимала JS-поток. В React Native
этот поток доставляет нажатия и «Назад», поэтому зависание выглядит полным.

1. **Пакет подключения расшифровывался одним синхронным проходом.** Подготовленное
   разрешение (`device-link/prepared`) содержит пространства целиком: мегабайты
   NIP-44 под одной подписью. `decryptPack` считал SHA-256 всего события и
   расшифровывал все части подряд. Замер в Node без JIT (ближе к Hermes) на пакете
   1,5 МБ: проверка подписи 3,8 с, NIP-44 7,9 с, всего 12,7 с; на телефоне
   дольше. Расшифровка шла:
   - при каждом раскрытии панели «Подключить другое устройство» (только чтобы
     показать «Подготовлено N досок»); каждое нажатие ставило ещё один проход в очередь;
   - после каждой проверки реплик на экране досок (`prepareDeviceLink()` →
     `preparationInfo()`).
2. **Проверка реплик досок перезапускалась под открытой доской.** Эффект в
   `BoardsScreen` зависел от `isOnline`/`networkType`, но не от фокуса. После
   паузы экран гаснет, Wi-Fi переподключается, NetInfo меняет тип сети, и экран
   досок под открытой доской заново проверял все реплики, а затем открывал
   пакет подключения (п. 1). Одновременно доска делала полную синхронизацию по
   возврату в приложение.
3. **Запросы к ноутбуку в локальной сети шли без срока.** У HTTP-клиента Android
   в RN нет собственного тайм-аута. Спящий ноутбук или IP из другой сети держали
   «Получить запрос» бесконечно; панель оставалась занятой, а повторные нажатия
   раскрывали и сворачивали её, запуская п. 1.

## Что изменено

- `deviceLink/protocol.ts`: `decryptPackSliced`, `encryptPackSliced`,
  `finalizeEventSliced`, `verifyEventSliced`. Хэш считается кусками по 16 КБ,
  NIP-44 по одной части; между ними поток возвращается UI, закрытый экран
  отменяет работу через `AbortSignal`. Проверки те же: подпись, адресат, MAC, лимиты.
- `deviceLink/service.ts`: рядом с пакетом хранится маленькая сводка
  `device-link/prepared-info`, и показ «Подготовлено…» читает только её.
  Пакет от старой сборки открывается один раз (порциями), после чего пишется
  сводка. Параллельные вызовы делят одну работу. Истёкшее разрешение равно
  отсутствию. Запросы к ноутбуку ограничены 10 с и отменяются.
- `DeviceLinkPanel`: кнопка «Отменить» во время операции. Свернуть панель или
  уйти из настроек тоже значит отменить. После ухода с экрана состояние не меняется.
- `BoardsScreen`: проверка реплик только на видимом экране и один раз на набор
  досок и тип сети. Повтор бывает только после неудачи.
- `shared/lib/stallWatch.ts`: сторож JS-потока. Пауза больше 1,5 с на активном
  приложении попадает в журнал с названием работы, которая шла. Если приложение
  закрыли во время тяжёлой работы, это записывается при следующем запуске.
- Настройки: версия показывает `2.1.0 · сборка 26 · <коммит>`, есть кнопка
  «Скопировать подробности» для журнала без ошибки.

## Проверка на телефоне

APK с versionCode 26 ставится поверх, данные не очищать. В «Настройки → Версии»
должна быть `сборка 26`.

1. Настройки → «Подключить другое устройство». Раскрыть и свернуть панель
   5–6 раз подряд: каждое нажатие отрабатывает сразу.
2. Ввести IP:порт, по которому никто не отвечает (например, `192.168.1.250:8080`),
   нажать «Получить запрос с ноутбука». Работает «Отменить», работает «Назад»;
   без отмены через 10 с появляется «Ноутбук не ответил за 10 секунд».
3. Открыть доску, погасить экран на 5–10 минут, вернуться. Доска отвечает
   на нажатия сразу.
4. Если зависание всё же было: перезапустить приложение, «Настройки →
   Скопировать подробности», прислать текст. Строки `ui:` покажут, что шло.
