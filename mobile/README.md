# p2pKanban Android

Изменения v2.0.0 и границы автономной синхронизации: [описание релиза](docs/product/v2.0.0-release-notes.md).

Самостоятельный React Native / Expo-клиент для Android. Локальный Rust-узел
нужен для первичного входа и выдачи ключа доски, но не является постоянным
посредником. После привязки клиент хранит полную локальную копию и
синхронизирует зашифрованный журнал напрямую через несколько Nostr-реле.

Текущая версия клиента и совместимого web/backend: `v2` (`2.0.0`). Каналов
stable/dev/beta больше нет: разработка непрерывна, а номер `vN` обозначает
отдельную продуктовую сессию.

## Что уже работает

- проверка и сохранение адреса узла;
- регистрация и вход;
- защищённое хранение rotating refresh token через Android Keystore;
- список пространств и досок с локальным кэшем;
- создание, изменение, архивирование и удаление пространств и досок при связи
  с узлом;
- создание, изменение и удаление колонок при связи с узлом;
- горизонтальная канбан-доска;
- полный CRUD карточек, архив и возврат из архива;
- два явных действия для карточки: локальное «Скрыть здесь» с возвратом и
  глобальное «Удалить везде» с tombstone;
- сенсорный перенос карточек между любыми колонками с прокруткой у края;
- создание, переименование и удаление чек-листов и их пунктов;
- независимые checklist/item delta: поздний снимок больше не заменяет соседний
  пункт и не удаляет пункты, которых в нём не было;
- метки и комментарии при связи с узлом;
- локальный снимок доски и очередь офлайн-изменений;
- автоматическая подготовка всех доступных досок после входа;
- независимая синхронизация карточек и чек-листов без включённого компьютера;
- шифрование XChaCha20-Poly1305 до отправки на relay;
- детерминированное разрешение параллельных изменений по
  `logicalClock -> replicaId -> eventId`;
- понятные состояния `нет связи`, `сохранено на устройстве`,
  `синхронизация` и `нужна проверка`;
- история доски без вывода сырого JSON;
- экран версий Android-клиента и подключённого backend, включая последнюю
  сохранённую версию узла вне LAN;
- светлая и тёмная системная тема.
- локальное системное напоминание для каждой карточки: одна карточка — не
  больше одного напоминания, дата и время хранятся как локальные компоненты
  телефона и не уходят на узел или relay;
- переход из Android-уведомления сразу к нужной карточке;
- синхронизация с web-настройками темы, плотности, палитры, акцента, фона доски,
  вида карточек и видимости описаний, дат и checklist-прогресса;
- плоская мобильная адаптация web-градиента без изменения исходного CSS-значения
  на сервере и загрузка удалённого wallpaper по `http(s)` URL.

Структурный CRUD, метки и комментарии требуют доступного узла. Карточки,
чек-листы и глобальное удаление синхронизированной карточки работают офлайн
через relay fallback.
Импорт/экспорт ещё не перенесён из web.

## Локальные напоминания

Напоминание настраивается в модальном окне карточки. Доступны ручные поля
`ДД.ММ.ГГГГ` / `ЧЧ:ММ` и быстрые варианты «Через час» и «Завтра 09:00».
Android запрашивает разрешение только при первом сохранении. Напоминание не
синхронизируется между устройствами: это намеренная локальная настройка.

В хранилище остаётся строка вида `2026-08-16T09:35`, без суффикса UTC. При
возврате приложения на передний план расписание сверяется с текущим часовым
поясом и при необходимости перестраивается. После выхода из аккаунта все
нативные расписания этого сеанса отменяются до очистки локальных данных.

## Первичная привязка телефона

На компьютере из корня p2pKanban:

```bash
python bootstrap.py start --listen lan
```

Bootstrap покажет адрес и выбранный порт. В приложении укажите его целиком,
например:

```text
http://192.168.1.42:49152
```

Только во время первичной привязки телефон и компьютер должны видеть друг
друга. Для Android Emulator адрес компьютера обычно начинается с
`http://10.0.2.2:`.

Локальный HTTP разрешён в Android manifest намеренно, потому что zero-config
bootstrap работает в LAN без TLS. Не публикуйте этот порт напрямую в интернет.

После входа клиент небольшими очередями получает отдельный 32-байтный ключ для
каждой доступной доски и сохраняет её snapshot. Ручное открытие каждой доски
перед уходом из локальной сети больше не требуется. Ключи сохраняются через
Android Keystore, а в Nostr уходят только:

- непрозрачный тег доски;
- зашифрованные snapshot/events;
- техническое время и размер сообщения.

Нормальная работа после привязки:

```text
Android local store <-> Nostr relay set <-> локальный узел, когда он включён
```

Компьютер может быть выключен. Телефон читает локальную копию, публикует
изменения в relay-журнал и получает события других уже привязанных реплик.
Tailscale, одна Wi-Fi-сеть и проброс порта для этого не нужны.

## Текущая граница roaming

Независимый путь охватывает чтение доски, создание, правку, перенос,
архивирование и tombstone-удаление карточек, а также полный CRUD чек-листов.
По Wi-Fi с доступным узлом Android отправляет изменение coordinator и затем
зеркалирует в relay. В мобильной сети при сохранённом LAN-адресе подготовленная
доска сразу использует relay, не ожидая таймаута недоступного частного адреса.
Локальное скрытие остаётся только в session-bound хранилище телефона и никогда
не публикуется.

Создание и изменение пространств, досок и колонок, метки и комментарии
остаются coordinator-операциями. Ключ доски является
capability владельца; полноценные роли общего workspace потребуют
owner-signed membership epochs и отдельной ротации ключей.

## Запуск для разработки

Нужны Node.js LTS и npm:

```bash
cd /path/to/p2pkanban-android
npm ci
npm start
```

Затем откройте проект в Expo Go либо запустите нативную сборку:

```bash
npm run android
```

## Локальная сборка APK

Нужны:

- JDK 17;
- Android Studio;
- Android SDK Platform 36 и Build Tools;
- заданная переменная `ANDROID_HOME` или `ANDROID_SDK_ROOT`.

Сборка одной командой:

```bash
npm ci
npm run apk
```

Готовый файл появится здесь:

```text
dist/p2pKanban-2.0.0.apk
```

Скрипт сначала проверяет установленный Expo, JDK и Android SDK Platform 36,
затем выполняет Expo prebuild, запускает Gradle `assembleRelease` и копирует
результат в стабильное место. Тестовая release-сборка подписывается стандартным
debug keystore нативного шаблона; для Google Play нужен отдельный production
keystore и AAB.

На Windows Expo запускается через текущий `node.exe`, а Gradle batch — через
`cmd.exe`; `npx.cmd` не используется. Пути с пробелами и кириллицей передаются
как отдельные аргументы. Проверка сборщика без Android SDK:

```bash
node --test scripts/apk-commands.test.mjs
```

`prebuild --clean` пересоздаёт `android/`, как и раньше: ручные native-правки
нужно переносить в Expo config/plugins до сборки. Если проблемы относятся к
самому узлу на компьютере, диагностика выполняется в **web-проекте** командой
`python bootstrap.py doctor`; установка APK не исправляет backend-миграции.

Самообновление APK напрямую из ветки GitHub намеренно не включено. Android не
может безопасно собрать и незаметно заменить собственный APK из исходников:
обновление должно быть заранее собрано и подписано тем же production key, а
установку всё равно подтверждает системный Package Installer. Следующий этап —
CI, который публикует подписанный APK/AAB в GitHub Release, либо Expo OTA для
JS/assets в пределах совместимого native runtime.

Альтернативный cloud build уже описан в `eas.json`:

```bash
eas build --platform android --profile preview
```

## Проверки

```bash
npm run typecheck
npm test
npm run check:contract
npm run export:android
```

Reducer-тесты закрепляют полный CRUD чек-листов, переназначение временных ID и
порядок офлайн-операций. Отдельные тесты проверяют drag-and-drop, XChaCha20
round-trip, отсутствие открытых данных в relay record, детерминированный merge,
нормализацию адреса и поиск health endpoint.

## Почему у mobile отдельный auth endpoint

Web продолжает хранить refresh token только в HttpOnly cookie. React Native
считает cookie-аутентификацию нестабильным местом, поэтому native password flow
возвращает собственный opaque refresh token. Android-клиент кладёт его только
в `expo-secure-store`, поворачивает при каждом refresh и удаляет вместе со
всем session-bound состоянием при выходе или смене узла.

Native endpoints:

```text
POST /api/v1/auth/native/sign-up
POST /api/v1/auth/native/sign-in
POST /api/v1/auth/native/refresh
POST /api/v1/auth/native/sign-out
```

Обычные web endpoints и их HttpOnly cookie не изменены.
