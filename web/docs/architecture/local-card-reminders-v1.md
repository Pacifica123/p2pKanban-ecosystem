# Локальные напоминания карточек v1

## Граница

Напоминание относится к карточке как смысловой единице, но остаётся настройкой
конкретного устройства. На одну карточку допускается не больше одного
напоминания. Backend API, PostgreSQL, roaming event и Nostr payload не меняются.

Дата хранится как floating local wall-clock `YYYY-MM-DDTHH:mm`, без `Z`, offset
и IANA timezone. Поэтому два устройства не обязаны согласовывать момент и не
могут случайно перетянуть локальное расписание друг друга.

## Android

- `expo-notifications` создаёт one-shot DATE trigger и отдельный channel;
- разрешение запрашивается только при явном сохранении пользователем;
- notification data содержит workspace/board/card IDs и открывает карточку;
- при активации приложения будущие записи сверяются с текущим timezone offset и
  перестраиваются, а просроченные удаляются;
- переименование и замена временного card ID обновляют расписание;
- hide/delete отменяют запись, а sign-out отменяет все native schedules до
  очистки session-bound storage.

Если часовой пояс изменился, пока приложение ни разу не активировалось, Android
может сначала сохранить исходный absolute trigger. Это осознанная граница v1,
а не повод вводить серверную timezone-синхронизацию.

## Web

Web хранит напоминания в `localStorage`, scoped по `userId`, и использует
`datetime-local`. При открытой вкладке ближайшая запись обслуживается timer;
после возврата вкладки просроченная запись сразу показывается как in-app toast.
Browser Notification является дополнительным каналом, если пользователь дал
разрешение. Закрытая вкладка не обещает фоновое срабатывание.

## Privacy

Текст карточки не уходит в отдельный сервис уведомлений. Android удаляет
расписания при выходе. Web не показывает и не запускает reminders другого
аккаунта, даже если тот использовал тот же browser profile.
