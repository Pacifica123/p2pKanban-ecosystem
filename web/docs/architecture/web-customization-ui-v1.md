# Web-интерфейс настройки внешнего вида v1

- Статус: базовая реализация готова
- Область: настройки пользователя и отдельной доски

## Цель

Дать пользователю заметную настройку интерфейса без произвольного CSS и без
расхождения между сохранённой серверной моделью и локальным preview.

## Экраны

### Настройки пользователя

Пользователь выбирает:

- тему;
- плотность интерфейса;
- уменьшение анимации;
- способ добавления пункта чек-листа;
- боковой или центральный режим раскрытия карточки.

Настройки применяются ко всему клиенту и сохраняются через appearance API.

### Настройки доски

Для доски доступны:

- фон из схемы, акцента, цвета, градиента, preset или изображения по URL;
- preset оформления;
- свой акцентный цвет;
- плотность карточек;
- визуальные параметры, разрешённые backend-контрактом.

Настройки доски не должны менять глобальные предпочтения пользователя.

### Точка применения

Board screen получает итоговые UI tokens из двух источников:

1. глобальные user appearance;
2. board appearance, которое переопределяет только разрешённую часть.

## Модель состояния

Есть три отдельных состояния:

- `persisted` — последнее подтверждённое backend значение;
- `draft` — текущий выбор в форме;
- `preview` — временно применённое отображение.

Preview не записывается автоматически. Cancel возвращает `persisted`. Save
отправляет нормализованную модель и после ответа обновляет `persisted`.

## Правила optimistic UX

Допустимо сразу показать выбранную тему, но:

- запрос должен иметь loading/error состояние;
- при ошибке preview откатывается;
- повторное сохранение не создаёт гонку;
- серверное значение остаётся источником истины для аккаунта и доски;
- неизвестный preset заменяется безопасным default.

## Граница server → UI

Backend хранит значения контракта, а frontend переводит их в CSS variables и
готовые presets. Акцент ограничен формой `#RRGGBB`; URL wallpaper проходит
отдельную HTTP(S)-проверку.

Пример:

```text
theme = dark
density = compact
accentColor = #a855f7
wallpaper = accent
```

Frontend преобразует это в ограниченный набор tokens. Значения проходят
validation и не вставляются как сырой HTML/CSS.

## Что не входит в v1

- загрузка wallpaper-файла в сам p2pKanban;
- публичный marketplace тем;
- пользовательский JavaScript;
- свободное редактирование CSS;
- сложный конструктор тем;
- синхронизация тем через coordinator-free transport.

## Проверки

- unit: mapping server model → UI tokens;
- integration: preview, cancel, save и rollback;
- API: чтение/изменение appearance только с допустимыми значениями;
- UIX: настройка пользователя и доски сохраняется после перезагрузки;
- безопасность: неизвестные строки не становятся исполняемым CSS/HTML.

## Результат

Пользователь может настроить внешний вид приложения, привычки работы с
карточками и вид доски в пределах проверяемого контракта. Модель остаётся
расширяемой, но не превращается в непроверяемый конструктор.
