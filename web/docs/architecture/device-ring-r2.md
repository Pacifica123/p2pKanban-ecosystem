# Кольцо устройств на web-узле (R2)

Этап R2 решения «кольцо устройств» ([docs/ecosystem/trusted-devices.md](../../../docs/ecosystem/trusted-devices.md)).
Контракты: [account-ring/1](../../../contracts/account-ring/1/SPEC.md),
[keyring/1](../../../contracts/keyring/1/SPEC.md). Патч `2026-10-07-web-ring-r2`.

## Что делает узел

- **Одно кольцо на локального пользователя.** Ключ устройства узла — ключ
  Nostr-роуминга (`TRANSPORTS__NOSTR__SECRET_KEY`). Без включённого роуминга
  экран кольца говорит, что его нужно включить.
- **`genesis`** пишет узел по кнопке «Создать кольцо». Relay кольца — relay
  узла с `wss://` (не больше 16; `ws://` контракт запрещает), кворум —
  `TRANSPORTS__NOSTR__MIN_RELAY_ACKS`, но не больше числа relay.
- **Перенос текущего доверия.** Устройства из `trusted_device_peers`
  (`device-link/2`, `web-node-link/1`), которых нет в кольце, показаны как
  «доверены по-старому». Владелец даёт имя и вид (web, Android, Linux),
  узел пишет `add` с `via: migration`, роль `admin` (решение владельца: все
  устройства admin). Ключ, которому узел не доверял, перенести нельзя
  (403): новое устройство входит по QR в R4.
- **Связка ключей.** При каждом обмене узел пересобирает свою копию: все
  пространства и доски владельца, ключ доски `roaming/1` текущей эпохи
  (производный ключ закрепляется в `roaming_board_capabilities`, как при
  экспорте узла). `rev` растёт при изменении и всегда выше любого `rev`,
  виденного у других устройств; исчезнувшая доска или пространство
  публикуется как `deleted: true` без ключа.
- **Обмен с relay** — по кнопке «Синхронизировать сейчас», после каждой
  записи в журнал и фоном раз в 10 минут. Узел публикует запечатанные для
  всех участников журнал (31990), связку (31991) и отметку присутствия (31992),
  забирает копии под тегом аккаунта, добавляет новые записи журнала (подпись
  проверяется у каждой записи), принимает связки и отметки только от
  участников. Итог последнего обмена (кто из relay принял, собран ли кворум,
  ошибки) хранится в `account_rings.last_sync_json` и виден на экране.
- **Разные версии.** По отметкам присутствия экран показывает версию каждого
  устройства и отставание (`presence_skew`): протоколы кольца, которых
  устройство не знает, и старый журнал.

## Чего R2 не делает

- Доски и пространства из чужих копий связки показаны, но в базу узла не
  импортируются (R3/R4: тогда же структура досок).
- Нет QR и встречи (R4), удаления и ротации ключей (R5).
- `device-link/2` и LAN-привязка работают как раньше; кольцо их не заменяет,
  пока mobile не умеет кольцо (R3).

## API

Все под `/api/v1`, нужна сессия.

| Метод | Путь | Что |
|---|---|---|
| GET | `/ring` | состояние: свёртка журнала, «доверены по-старому», связка (сводка и элементы с признаком `onThisNode`), отметки, отставание, последний обмен |
| POST | `/ring/genesis` | `{name}` — создать кольцо |
| POST | `/ring/migrate` | `{publicKey, name, kind}` — перенести доверенное устройство |
| POST | `/ring/rename` | `{publicKey, name}` |
| POST | `/ring/sync` | обмен с relay сейчас |

Таблицы — миграция `0024_account_ring.sql`.

## Проверка

- `cargo test -p p2p-kanban-nostr-transport --test ring_contract_vectors` —
  свёртка всех векторов `ring-*.json` в прямом и обратном порядке, вскрытие
  `sealed-ring-log`, `sealed-keyring`, `presence` своим ключом и отказ чужому,
  слияние и digest `merge.json`, журнал из `welcome` встречи;
- `TEST_DATABASE_URL=… cargo test --test ring_r2_smoke -- --ignored` — на
  Postgres: genesis, перенос, отказ чужому ключу, связка после обмена с
  недоступными relay, приём копий телефона (переименование, пространство из
  поездки, старая версия) и отказ копии чужого устройства;
- `npx vitest run src/test/unit/features/deviceLink`.

На хосте (Docker): создать кольцо, перенести телефон, нажать «Синхронизировать
сейчас» и увидеть «кворум relay собран».
