# p2pKanban: roaming и новые доски

Базы патчей: web `853d30f`, Android `65fea82`, приложенные 13 сентября. Web-патч применяется на ПК и ноутбуке, Android-патч — к исходникам клиента. Это дополнения к текущим архивам, а не замена прошлому bootstrap-патчу.

## Причины

Android обращается к HTTP-адресу выбранного узла. Частный LAN-адрес ПК недоступен через обычный мобильный интернет. Relay переносит события подготовленных досок, а не произвольные HTTP API-запросы. Поэтому ошибка «Подготовить доступ» сама по себе не доказывает отказ relay. Для установления причины отказа relay на телефоне нужны его собственные результаты диагностики.

Backend ноутбука опрашивает relay только для уже известных board IDs. Доска, импортированная после pairing, отсутствует в его базе; её ID и ключ ему не передавались. Общая LAN и обновление страницы этого не исправляют. Телефон видел новую доску через API ПК, а ноутбук обращался к собственной базе. Это ограничение протокола обнаружения, а не ошибка отрисовки.

## Изменения

Android сохраняет действующее разрешение при сетевом отказе; подготовленная подпись используется без нового HTTP-запроса. После успешной подготовки досок владельца клиент пытается заранее получить разрешение. Смена аккаунта во время запроса не позволяет записать результат в другую сессию. Истёкшие подписи не используются.

Кнопка «Получить свежий доступ от ПК» явно обновляет снимок; при отказе объясняет возможность использовать сохранённый. Есть «Проверить relay без ПК»: показывает доступность relay-чтения для подготовленных досок, адреса ошибок и количество подписанных событий, без ключей. Успешное чтение не означает подтверждённой доставки локальных изменений.

Сетевые ошибки/5xx при обновлении сессии не стирают локальную сессию; 401/403 остаются отказом авторизации. Неудачный системный internet probe не отключает обращения к LAN при физически подключённой сети. Отказ HTTP и отказ relay отображаются отдельно; преждевременное закрытие WebSocket завершается ошибкой сразу. После недоступности ПК учитывается пауза между повторными HTTP-попытками при успешном relay.

Web получил режим дополнения уже подключённого узла: «Получить новые доски от доверенного устройства». Он использует существующий зашифрованный device-link обмен. Принятие требует авторизации, того же user ID, подтверждённого отправителя, правильного recipient, действующей цепочки и одноразового запроса со сроком. Корневой ключ должен быть ранее известен аккаунту через действующую локальную запись доверия. Пространство должно уже принадлежать локальному пользователю; epoch должен совпадать.

Добавляются только отсутствующие доски и связанные записи. Существующие, в том числе удалённые доски, пропускаются; пароль, профиль, настройки и старые доски не заменяются. Tombstones учитываются; коллизии приводят к откату. Nonce поглощается в той же транзакции. Новые пространства и смена epoch этим режимом не импортируются.

Также исправлен слишком короткий допуск запуска процесса в npm watchdog-тесте из предыдущего патча. Рабочие таймауты bootstrap не менялись. Android build code — 21; проверка версий согласована с ним.

## Применение и получение новой доски

1. Положить соответствующий ZIP в `patches/` каждого workspace: `devctl plan`, затем `devctl start`.
2. На ПК и ноутбуке пересобрать/запустить web из корня проекта: `python bootstrap.py start --source-dir .`. Не выполнять reset.
3. Android: собрать APK обычной командой `npm run apk`, установить поверх имеющегося приложения. Не удалять приложение/его данные: там находятся локальные ключи и очередь изменений.
4. На ноутбуке войти в подключённый аккаунт. На странице пространств открыть «Получить новые доски от доверенного устройства» и создать запрос на 10 минут.
5. Передать запрос ПК через панель «Разрешить новое устройство» либо телефону. Телефон должен получить свежий снимок **после появления новой доски**, пока ПК доступен. После этого он может подтвердить запрос вне LAN и без ПК. Если данные никогда не покидали недоступный ПК, телефон их получить не сможет.
6. Сверить отпечатки на устройствах, подтвердить, передать зашифрованный ответ ноутбуку. Выбрать «Принять новые доски». Новый пароль и очистка базы не нужны. Список досок обновится. Повторное применение того же ответа отклоняется; новый обмен пропускает уже имеющиеся доски.

## Проверка телефона

В LAN открыть список досок, дождаться подготовки. В панели подключения проверить дату, количество досок и срок разрешения. На мобильном интернете сразу использовать сохранённое разрешение; обновление через LAN-адрес ПК не требуется. Нажать «Проверить relay без ПК», затем открыть подготовленную доску. При отказе прислать текст этой диагностики: он отделяет отсутствие capability от сетевой недоступности relay.

## Оставшиеся ограничения

**Автоматический каталог пространства через relay не реализован.** Дополнение — явный повторный обмен, а не полная автоматическая синхронизация. Структура, комментарии и права существующих досок не получают полной автономной синхронизации. Телефон не становится прокси. Доступность/retention relay и задержка отзыва прав на отключённых устройствах сохраняются.

Для автоматического обнаружения нужны workspace-scoped discovery key и authority, подписанные объявления новых досок, доставка board capabilities, отзыв/epoch, tombstones и восстановление после пропущенных событий. Принятие неизвестных `board.snapshot` без такого протокола недопустимо.

Проверки: TypeScript обоих клиентов, web production build, Android device-link/roaming tests, Rust с `nostr-shadow`, применение через devctl. Реальное межмашинное испытание с PostgreSQL, Android и мобильным оператором здесь не выполнено. Отсутствие сетевых ошибок после патча не обещается без проверки relay на телефоне.
