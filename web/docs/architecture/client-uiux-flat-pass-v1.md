# UI/UX-проход: плавная и плоская доска

- Статус: реализовано в следующем патче после `v1.0.0-beta.3`
- Основание: размеченный светлый скриншот и повторная проверка актуальной
  фиолетовой темы от 26 июля 2026 года
- Область: основной web-клиент

## Целевой принцип

Доска является рабочим полотном. Навигация, сводка, синхронизация, история и
настройки помогают работе, но не должны выглядеть такими же важными, как
колонки и карточки.

`Flat` здесь означает:

- меньше вложенных панелей, рамок и тяжёлых теней;
- меньше постоянных элементов;
- один уровень визуального акцента на действие;
- техническая информация скрыта до запроса;
- интерфейс не дёргается при hover, drag или появлении статуса;
- используемые слова понятны без знания внутренней архитектуры.

## Разбор карты проблем

| Наблюдение | Состояние на актуальном скриншоте | Решение |
|---|---|---|
| Смесь русского и английского | Осталась почти везде: `Workspace switcher`, `Board summary`, `Create column`, `Board activity`, `Sign out` | Основной пользовательский путь переведён на русский: вход, пространства, доски, колонки, статусы, история и настройки оформления |
| Нужен «дзен-режим» | Боковая панель постоянно отнимает ширину | В верхней панели добавлено постоянное сворачивание навигации; выбор хранится локально |
| Кнопки настройки сливаются с обычной навигацией | Заголовок `CUSTOMIZATION` не создавал отдельного режима | Настройки собраны в сворачиваемую нижнюю группу; есть отдельные пункты вида приложения и текущей доски |
| Список досок расположен странно и оставляет пустоту | На новом скриншоте заголовок есть, а полезная часть визуально теряется | Пространства и доски стали независимыми сворачиваемыми группами со счётчиком и ограниченной прокруткой |
| `kanban` возле каждой доски — лишняя информация | Тип повторяется и ничего не различает | Тип убран из бокового списка и карточек списка досок |
| Верхняя шапка слишком высокая | Технический заголовок про session baseline занимал целую строку | Шапка уменьшена до панели навигации и аккаунта |
| Имя, email и две кнопки выхода занимают много места | На актуальном скриншоте блок всё ещё широкий | Оставлен компактный аватар и имя; email и оба варианта выхода перенесены в меню аккаунта |
| Кнопки доски состоят из emoji | Иконки неодинаково выглядят в разных ОС и шрифтах | Emoji заменены единым набором простых SVG-иконок |
| `Board summary` слишком крупная | Четыре карточки статистики занимают место над рабочей областью | Сводка стала одной строкой `колонки · карточки · время`; описание и тема открываются по нажатию |
| Создание колонки занимает отдельную большую панель | На актуальном экране оно конкурирует со сводкой | Добавление колонки перенесено в конец горизонтальной ленты и раскрывается только по запросу |
| Фон доски отсутствовал | Уже исправлено до этого прохода: фиолетовый preset и wallpaper видны | Сохранено; фон теперь занимает плоскую рабочую поверхность без ещё одной тяжёлой рамки |
| Колонки должны прокручиваться по горизонтали | Базовая прокрутка уже существовала | Сохранена и усилена: независимый горизонтальный scroll, snap и тонкий scrollbar |
| Drag в заполненную колонку визуально ломает компоновку | Порядок уже был исправлен, но визуально ghost и drop-zone меняли плотность | Компоновщик карточки закреплён отдельно, список имеет стабильную минимальную высоту, ghost не принимает pointer events; добавлены два теста порядка и отсутствия потерь |
| Пустая колонка дважды сообщает одно и то же | Заголовок и описание повторяли смысл | Оставлена одна спокойная строка внутри стабильной drop-zone |
| Activity feed постоянно занимает правую треть | На фиолетовом скриншоте проблема осталась и стала заметнее | История перенесена в вызываемую боковую панель; доска использует всю ширину |
| Activity feed показывает сырой JSON | Технический payload оставался основным содержимым события | Событие получает понятное название, автора, время и изменённые поля; JSON спрятан в `Технические детали` |
| Sync показывает `replica`, `server order`, `pull` и сырой `429` | На актуальном скриншоте это отдельная красная полоса; найден повторный auto-pull после каждого `pulling → ready` | Цикл запросов устранён и закреплён тестом «один pull на replica + workspace»; обычный UI показывает только понятные состояния, а внутренняя причина свёрнута |
| Hover делает интерфейс дёрганым | Кнопки физически поднимались на один пиксель | Геометрия при hover больше не меняется; меняются только цвет и граница |
| Слишком много скруглений, теней и «карточек внутри карточек» | Фиолетовая тема изменила цвет, но не визуальную массу | Радиусы уменьшены, тяжёлые тени убраны, фон стал ровнее, шапки и сводка переведены в строки-разделители |

## Иерархия после прохода

1. Главный уровень — колонки и карточки.
2. Заголовок доски и основные действия — одна компактная строка.
3. Сводка и локальные статусы — короткие строки.
4. История, технические причины и настройки — только по запросу.
5. Навигация может полностью исчезнуть и вернуть доске ширину.

## Что намеренно не включено

- Полный новый дизайн карточки и её drawer.
- Сенсорный drag-and-drop для мобильных устройств.
- Автоматическое обновление приложения из браузера.
- Новый набор загружаемых изображений для wallpaper.
- Пиксельный visual regression.

Кнопка обновления в браузере пока не добавляется: локальный updater имеет
доступ к Docker, backup и переключению images. Выдавать такой control plane
обычной web-сессии без отдельной локальной авторизации опасно. Пользовательский
вход остаётся командой `python bootstrap.py update`.

## Проверки

- unit/integration frontend-тесты;
- production Vite build;
- отдельные тесты переноса карточки внутри заполненной колонки и между
  колонками;
- проектный UI/UX Evidence Runner;
- ручная проверка светлой и тёмной темы при доступном Chromium.

Если системный Chromium отсутствует, runner обязан вернуть
`skipped_prerequisite`, а не считать визуальную проверку успешной.
