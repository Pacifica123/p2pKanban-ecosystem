# ADR-007: доска как набор независимых реплик

Статус: accepted  
Дата: 2026-07-28  
Заменяет для roaming-пути решение ADR-006 о постоянном coordinator fallback.

## Контекст

p2pKanban должен сохранять три свойства одновременно:

1. компьютер и телефон не зависят друг от друга и могут быть выключены по
   отдельности;
2. уже привязанная реплика получает актуальный журнал доски из сети хранения и
   не требует доступности «главного» компьютера;
3. офлайн-операции канбана применяются сразу локально и сходятся после обмена.

Приватная mesh-сеть решает адресацию, но не хранение. Iroh даёт хороший прямой
канал между одновременно доступными peers, но сам по себе не заменяет
store-and-forward. Поэтому ни Tailscale, ни один постоянно включённый
координатор не могут быть обязательной частью roaming-пути.

## Решение

- Каждое устройство хранит полный локальный snapshot уже открытой доски и свой
  append-only журнал операций.
- Nostr используется как зашифрованный store-and-forward между репликами.
- Операция считается опубликованной только после подтверждения минимум двух из
  трёх настроенных реле.
- Используются обычные сохраняемые kinds `1978` и `1979`. Ephemeral-диапазон
  `20000..29999` запрещён для журнала доски.
- Для каждой доски backend выводит отдельный 32-байтный capability key и
  непрозрачный `boardTag`. Релей не видит workspace ID, board ID, названия,
  карточки или пользователя.
- Содержимое шифруется XChaCha20-Poly1305 до публикации. Nostr-подпись
  обеспечивает целостность транспортного события; знание ключа доски даёт
  право читать и создавать события beta-протокола.
- Merge выполняется по полям. Победитель определяется одинаково на всех
  репликах кортежем `(logicalClock, replicaId, eventId)`.
- Backend является одной из реплик. Когда он включён, bridge публикует изменения
  web-клиента и применяет события мобильных реплик к PostgreSQL.
- Iroh может быть добавлен как быстрый прямой путь, но не является условием
  доступности данных.

## Первичная привязка

Узел требуется один раз для аутентификации, проверки прав администратора и
выдачи capability конкретной доски. После сохранения capability в Android
Keystore телефон работает с локальной копией и Nostr-реле напрямую.

Новая установка без ключа доски не может расшифровать relay-журнал. Передача
ключа между устройствами и owner-signed membership epochs являются следующим
этапом, а не скрытой зависимостью от постоянно включённого узла.

## Граница первого рабочего среза

Roaming v1 синхронизирует snapshot доски и операции с карточками: создание,
изменение полей, перенос и архивирование. Создание workspace, доски и колонок,
общие роли, отзыв устройства и ротация ключа остаются за пределами этого среза.

Эта граница должна быть видна в UI и документации. Она не разрешает возвращать
постоянную зависимость от домашнего компьютера для уже привязанной доски.
