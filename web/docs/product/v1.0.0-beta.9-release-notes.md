# p2pKanban v1.0.0-beta.9

## Главное

Исправлена причина исчезновения и взаимной замены пунктов чек-листа. Ранее
каждое checklist-событие уходило в roaming как полный снимок карточки. Поздний
снимок мог принять отсутствие нового пункта за удаление, а одинаковый
`columnId` — за перемещение карточки.

Beta.9 передаёт отдельную delta конкретного чек-листа или пункта. Legacy
снимки объединяются только аддитивно и не удаляют отсутствующие сущности.
Activity теперь создаётся только для фактически изменившихся полей. Миграция
`0015` удаляет однозначно ложные legacy-записи `card.moved`, созданные этим
сценарием.

## Клиенты

- web/backend: `1.0.0-beta.9`;
- Android: `1.5.0-mobile.7`.

Обновить нужно backend/web и Android. Старые клиенты продолжают понимать
базовый roaming v1, но не дают новой гарантии независимых checklist-delta.

## Android вне домашней сети

Если доска уже подготовлена и адрес узла является LAN-адресом, Android в
мобильной сети не ждёт таймаут HTTP-узла: изменения карточек и чек-листов сразу
публикуются в зашифрованный relay-журнал. Первичная привязка, выдача capability,
новые пространства, доски и колонки всё ещё требуют доступного coordinator.

## Интерфейс

- В web показаны версии web-клиента и backend.
- В Android показаны версия приложения и последняя известная версия
  подключённого backend.
- История использует согласованные русские формы: «Чек-лист создан»,
  «Пункт чек-листа создан» и читаемые названия полей.
- Счётчики используют правильные формы для 1, 2–4, 5–20 и следующих десятков.

## Проверка после обновления

1. Создать подряд несколько пунктов одного чек-листа и дождаться relay sync.
2. Убедиться, что все пункты остаются на web и Android после повторного pull.
3. Изменить и удалить один пункт; соседние пункты не должны измениться.
4. Проверить, что история содержит checklist-действия без ложного
   «Карточка перемещена».
5. Отключить Wi-Fi телефона, оставить мобильный интернет и изменить
   подготовленную карточку: очередь должна уйти через relay без ожидания LAN.
