# p2pKanban v1.0.0-beta.13

Дата: 2026-08-21

## Исправлено

- Updater больше не привязывается к source checkout devctl, если реальный
  Docker deployment работает из другой исторической копии.
- Добавлена безопасная команда `python bootstrap.py adopt-running` для узлов,
  оставшихся на beta.10 в `UserTestSpace`.
- Усыновление проверяет единственный Compose stack, published gateway port,
  одинаковую версию backend/web, `healthz`, PostgreSQL data volume и secrets
  volume.
- Controller переносится в постоянный
  `<devctl-workspace>/runtime/p2pkanban-node`; контейнеры и volumes при этом не
  перезапускаются, не переименовываются и не копируются.
- Source checkout хранит только код. Registry находится в workspace `.devctl`,
  а обычные bootstrap-команды автоматически делегируются runtime root.
- Updater получает `webPort` существующего узла из восстановленного state,
  поэтому Origin `http://127.0.0.1:8082` больше не отклоняется как чужой.

## Полевой сценарий миграции

Подтверждён исходный deployment:

- версия `1.0.0-beta.10`;
- images `1.0.0-beta.10-68c7d79968c3`;
- gateway `127.0.0.1:8082`;
- Compose project `p2pkanban-bootstrap`;
- volumes `p2pkanban-bootstrap_postgres_data` и
  `p2pkanban-bootstrap_bootstrap_secrets`.

Devctl-патч выполняет adoption после всех статических и production build gates.
После push работающий beta.10 web получает предложение обновиться до beta.13;
обычное UI update создаёт PostgreSQL backup до переключения images.

## Проверено

- unit-регрессии discovery/state/registry/runtime provisioning;
- zero-config bootstrap contract;
- production frontend build и web-тесты;
- Rust check/test/release build;
- применение devctl-патча к чистой beta.12-копии;
- отсутствие tracked/runtime secrets в payload.

Нативный Android payload не меняется: совместимой линией остаётся mobile.9.
