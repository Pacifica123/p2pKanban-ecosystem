# Текущее состояние v1 и направление v2

- Актуально на: 2026-08-25
- Текущая версия web/backend/Android: `v1` (`1.0.0`)
- Линия разработки: непрерывная, без каналов stable/dev/beta

`v1` фиксирует итог текущей сессии развития. Исторические beta/mobile номера
остаются только в старых release notes и image tags. Политика номеров описана
в [`version-policy.md`](version-policy.md).

## Встроенная roadmap-доска

Seed `P2P Planner roadmap / План работ по проекту` обновляет и существующую
демонстрационную доску: известные этапы v1 переводятся в колонку `Готово`, а
карточки v2 создаются либо приводятся к актуальным колонкам, описаниям и
приоритетам.

| Колонка | Карточка v2 | Приоритет |
|---|---|---|
| Готово | Пригласительные ссылки и права доступа | Без приоритета |
| Сейчас | Rich text в карточках | Высокий |
| Далее | Интеграция с GitHub | Высокий |
| Далее | Интеграция с devctl | Средний |
| Потом | Интеграция с Obsidian | Средний |

Права и приглашения закрыты первыми: сервер различает owner/member/guest,
приглашение одноразовое и хранится только как hash, а принятие, смена роли и
отзыв увеличивают access epoch, отзывают старые authorizations и ротируют
capability досок. Поэтому отложенная запись со старого устройства больше не
может вернуться после отзыва доступа. Следующая активная карточка — rich text.
GitHub следует до devctl: сначала нужен проверяемый внешний source contract,
затем UX применения патчей и receipts. Obsidian оставлен после них, чтобы не
закрепить формат двусторонней синхронизации раньше rich text.

## Честные границы v1

- Rust/PostgreSQL backend остаётся канонической точкой auth, прав и обычного
  принятия общих изменений.
- Web не строит все проекции только из sync-log; активные поверхности используют
  безопасный polling.
- Первый телефон или новая доска требуют первичного получения capability от
  доступного узла.
- ACK реле означает только «реле приняло»: Android хранит операцию как sync debt
  до подтверждения coordinator и показывает это отдельным состоянием.
- Локальные browser/Android snapshots не зашифрованы отдельным device key.
- Import создаёт новую копию и не выполняет destructive merge.
- Android self-update требует подписанного APK/OTA-контура; обновление из GitHub
  source само по себе APK не заменяет.

## Обычный путь

1. Запустить `python bootstrap.py`.
2. Работать через закреплённый URL узла.
3. Подключить Android и дождаться первичной подготовки нужных досок.
4. Сохранять прикладной backup перед значимыми изменениями.
5. Принимать commit-плашку web либо использовать `python bootstrap.py update`.
6. Останавливать stack через `python bootstrap.py stop`; volumes сохраняются.

Историческая оценка прежнего stable-кандидата сохранена в
[`stable-v1-readiness-2026-07-29.md`](stable-v1-readiness-2026-07-29.md), но не
определяет текущую политику выпуска.
