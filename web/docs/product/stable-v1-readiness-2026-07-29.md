# Архивная оценка прежнего stable-кандидата v1

> Исторический документ. С 2026-08-23 каналов stable/dev/beta нет; актуальная
> политика описана в [`version-policy.md`](version-policy.md).

- Дата оценки: 2026-07-29; обновлено: 2026-08-21
- Проверяемая линия: `v1.0.0-beta.13`
- Вердикт: функционально близко, релизно ещё не готово

## Что изменилось в оценке

Старый список блокеров был составлен до beta.4–beta.6 и ошибочно смешивал
недостающие функции с недостающими доказательствами. Основной web CRUD,
чек-листы, комментарии, внешний вид, bootstrap и полезный Android-клиент уже
существуют. Удерживать stable из-за отсутствия GitHub, Iroh или полного
coordinator-free режима больше не требуется.

Текущие блокеры относятся к воспроизводимости, данным и честной границе
релиза.

## Причина бага Android → web

Проблема состояла из трёх независимых частей:

1. при наличии roaming capability Android публиковал операцию сразу в relay и
   удалял её из очереди, не отправляя доступному coordinator;
2. исторические клиенты использовали отдельное поле состояния карточки, что
   усложняло совместимость с колонками;
3. открытая web-доска не обновляла список карточек автоматически.

Beta.6 изменила порядок на coordinator-first с relay fallback и обновляет
активные web-запросы. Beta.11 окончательно удалила фиксированное поле состояния
из wire/domain модели. Это закрывает найденную техническую
причину, но не отменяет проверку на реальных устройствах.

## Причина бага web → web

Два bootstrap-экземпляра имеют разные PostgreSQL и deployment secrets.
Обычный sign-in никогда не обращался к соседнему узлу, а одинаковый email был
уникален только внутри каждой БД. Повторная регистрация поэтому корректно, но
неочевидно создавала другой UUID. Кроме того, board keys выводились из разных
backend master keys.

Beta.7 добавляет явный link чистого узла: исходный backend проверяет пароль,
передаёт versioned snapshot и per-board capability, а целевой применяет их
одной транзакцией и создаёт локальную сессию. Реальный Windows/Linux прогон всё
равно остаётся обязательным доказательством stable.

Beta.8 разделяет локальное скрытие и глобальное удаление. Глобальная операция
создаёт tombstone, передаёт `card.delete` через общий relay и не принимает
запоздавший `card.put`. Кодовый контракт закрыт, но offline/reconnect и
доставка на реальных Windows/Linux/Android остаются частью release evidence.

Beta.9 заменяет checklist full-snapshot на entity-delta, не позволяет legacy
снимку удалять отсутствующие пункты и пишет activity только для фактических
изменений. Android на cellular с LAN-адресом узла использует relay-first.
Автотесты и Metro export являются кодовым сигналом; многосуточный и
cross-client прогон на реальных устройствах остаётся обязательным.

Beta.11 добавляет board-appearance roaming, tombstone-aware checklist merge,
конкурентный relay pull и защиту web от 401 storm. Это кодовый сигнал; реальная
матрица с длительно отключённым узлом всё ещё обязательна.

## Обновлённые критерии stable

Stable можно выпускать, если одновременно выполнены условия:

1. точный tagged commit дважды проходит
   `release-gates --profile full-local-release`;
2. один и тот же ZIP запускается на Windows и Linux;
3. тестовые данные переживают stop/start, update, rollback и отдельный restore;
4. cross-client CRUD проходит web ↔ Android и web ↔ web в обе стороны;
5. граница Android объявлена явно и соответствует результатам проверки;
6. лицензирование решено;
7. опубликованы SHA-256 и evidence bundle без секретов.

## Что не должно задерживать v1

GitHub/devctl, другие providers, coordinator-free membership, Iroh в web,
MFA/passkeys и destructive import — следующие продуктовые срезы. Их отсутствие
должно оставаться в limitations, а не превращаться в бесконечный релизный
блокер.
