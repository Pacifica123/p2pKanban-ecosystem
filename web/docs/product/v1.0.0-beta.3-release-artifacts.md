# Артефакты релиза v1.0.0-beta.3

- Тег: `v1.0.0-beta.3`
- Тип: GitHub Pre-release
- Основной способ развёртывания: self-host через Docker Compose

## Обязательные файлы релиза

| Файл | Назначение |
|---|---|
| `p2pkanban-v1.0.0-beta.3-bootstrap.zip` | Готовый исходный self-host комплект |
| `SHA256SUMS.txt` | SHA-256 основного архива и дополнительных бинарных файлов |
| `release-gates_*.zip` | Доказательства последнего полного прогона |
| Source code `.zip` / `.tar.gz` | Автоматические архивы GitHub по тегу |

Основной ZIP создаётся командой:

```bash
python tools/build_release_bundle.py --require-tag
```

Для пробной локальной сборки до коммита:

```bash
python tools/build_release_bundle.py --allow-dirty
```

Скрипт не кладёт в архив `.env`, секреты, `.git`, `node_modules`, `target`,
логи, БД, старые релизные файлы и результаты проверок.

## Что находится в bootstrap ZIP

```text
p2pkanban-v1.0.0-beta.3-bootstrap/
  README.md
  README_RELEASE_RU.md
  README_RELEASE_EN.md
  BUILD_INFO.json
  VERSION
  bootstrap.py
  tools/container_bootstrap.py
  deploy/bootstrap/
  backend/
  frontend/
```

Внутри нет заранее собранного Windows `.exe` или AppImage. Они больше не нужны
для основного пути: backend и frontend собираются в контейнерах, а пользователю
на хосте нужны только Python и Docker Compose v2.

## Какие сборки реально нужны

Обязательны:

1. production-сборка Rust backend внутри `deploy/bootstrap/backend.Dockerfile`;
2. production-сборка web-клиента внутри `deploy/bootstrap/frontend.Dockerfile`;
3. основной bootstrap ZIP;
4. файл контрольных сумм;
5. финальный пакет результатов release gates.

Опциональны:

- контейнеры `linux/amd64` и `linux/arm64`, опубликованные в OCI registry;
- offline-пакет сохранённых Docker images;
- подпись `SHA256SUMS.txt`;
- SBOM для контейнеров;
- отдельный Windows backend `.exe` для разработчиков;
- отдельный Linux backend binary.

Опциональные бинарники нельзя выдавать за самостоятельное приложение: им всё
равно нужны PostgreSQL, web-клиент и корректный runtime-конфиг.

## Проверка основного артефакта

1. Собрать архив из чистого commit с точным тегом.
2. Распаковать его в новый каталог.
3. Запустить:

   ```bash
   python bootstrap.py
   ```

4. Зарегистрироваться и проверить цепочку:
   workspace → board → column → card.
5. Проверить редактирование и перенос карточки.
6. Остановить приложение через `python bootstrap.py stop`.
7. Запустить снова и убедиться, что данные сохранились.
8. Проверить `python bootstrap.py status` и `logs`.
9. Выполнить `reset --yes` только на тестовых данных и убедиться, что появился
   чистый экземпляр.
10. Сверить SHA-256 скачанного ZIP.

Минимум один такой прогон нужен на Windows с Docker Desktop и один на Linux с
Docker Engine. До этого beta.3 остаётся кандидатом, а не подтверждённым
артефактом.
