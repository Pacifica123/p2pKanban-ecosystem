# p2pKanban v1.0.0-beta.7

## Главное

- Исправлена модель двух независимых web-установок: обычный вход теперь явно
  обозначен как локальный для открытого deployment.
- На чистом втором узле появился режим «Подключить с другого узла». Он
  переносит ту же identity, owned workspaces, доски и содержимое с основного
  узла по доверенной локальной сети.
- Пароль проверяется исходным узлом, но password hash, сессии, device records и
  deployment secrets не копируются. Целевой узел заново хэширует пароль и
  создаёт собственную сессию.
- Per-board roaming capability переносится отдельно от backend master key,
  поэтому два узла могут читать один зашифрованный журнал карточек и чек-листов.
- Backend roaming получил отдельный `nodeReplicaId`; workspace ID больше не
  используется как replica identity двух разных узлов.
- Концепция GitHub/devctl уточнена: `SourceConnector` обнаруживает изменения,
  provider adapter нормализует их, а общий inbox/rule runtime применяет
  разрешённые команды p2pKanban.

## Совместимость и миграция

Миграция `0013_web_node_link_identity.sql` создаёт локальную identity backend и
таблицу импортированных board capabilities. Существующие данные не
переписываются. Обычный single-node сценарий продолжает выводить ключи из
локального master key.

Для первого link оба web-узла должны быть обновлены до beta.7. Целевой узел
должен быть пустым. Автоматическое слияние независимо зарегистрированных
пользователей с одинаковой почтой намеренно запрещено.

## Проверка после обновления

1. На основном компьютере запустить beta.7 с `--listen lan`.
2. На ноутбуке убедиться, что в локальной копии нет уникальных данных, и при
   необходимости выполнить `python bootstrap.py reset --yes`.
3. Запустить beta.7 на ноутбуке, выбрать «Подключить с другого узла» и указать
   LAN-адрес основного web, email и пароль.
4. Проверить список workspace, досок, карточек, чек-листов и оформление.
5. Изменить карточку и пункт чек-листа по очереди на каждом web-узле и
   дождаться relay-синхронизации.

Beta.7 остаётся prerelease: web-node link и двусторонний roaming должны пройти
реальную матрицу Manjaro ↔ Windows вместе с полными release gates.
