# p2pKanban v1.0.0-beta.6

## Главное

- Исправлен путь Android → backend → web: мобильная очередь использует
  coordinator первым и Nostr-релеи как fallback.
- Roaming-ingest нормализует legacy-статусы Android и умеет создавать,
  изменять и удалять чек-листы с пунктами.
- Принятые roaming-изменения попадают в activity, outbox и статистику.
- Открытая web-доска автоматически обновляет карточки, чек-листы, метки,
  комментарии и историю.
- Android-клиент закрывает базовый CRUD workspace, досок, колонок, карточек,
  чек-листов, меток и комментариев.
- Карточку Android можно перетащить в любую колонку с прокруткой у края экрана.
- Документация выровнена с текущей beta, добавлены stable-readiness audit,
  PostgreSQL restore runbook и концепция GitHub/devctl.

## Совместимость

Миграция `0012_roaming_activity_echo_guard.sql` только запрещает повторно
зеркалировать activity, уже пришедшую из roaming, и не меняет пользовательские
данные. Схема локального Android snapshot повышается до 3 и принимает
сохранённые схемы 1–2. Web/backend beta.6 совместимы с данными beta.5.

Для полного cross-client исправления нужны оба обновления: main/backend beta.6
и Android `1.4.0-mobile.5`. Старый Android-клиент продолжит запускаться, но не
получит новый CRUD и coordinator-first flush.

## Проверка после обновления

1. Создать карточку в Android при доступном узле.
2. Убедиться, что она появилась на открытой web-доске без ручной перезагрузки.
3. Изменить и перенести карточку в web, затем обновить Android.
4. Создать, переименовать, отметить и удалить пункт чек-листа в обе стороны.
5. Повторить создание Android при недоступном узле, затем включить узел и
   проверить догоняющую синхронизацию.

Beta.6 остаётся prerelease до полного release-gates и cross-client acceptance
на итоговом APK.
