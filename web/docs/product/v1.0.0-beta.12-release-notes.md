# p2pKanban v1.0.0-beta.12

Дата: 2026-08-21

## Исправлено

- Production-сборка web снова проходит: миграция старых local-first операций
  больше не ломает TypeScript discriminated union.
- Backend собирается Rust 1.88: десериализация явного `null` для обновляемых
  полей карточки корректно возвращает двухуровневый `Option`.
- Проверка нового commit работает даже после перезапуска компьютера, когда
  Docker-контейнеры поднялись автоматически, а локальный UI-установщик ещё нет.
- Сравнение версии опирается на revision реально запущенного web image, а не на
  Git HEAD, который devctl уже мог передвинуть новым commit.
- Успешный `bootstrap.py start` записывает версию, image tag и commit собранного
  source; revision также встраивается в web bundle.
- Локальный UI-установщик запускается до долгой Compose-сборки, поэтому старый
  интерфейс продолжает видеть предложение обновления и при ошибке новой сборки.
- Devctl будит UI-установщик после успешного push; отдельный
  `bootstrap.py watch-updates` делает то же без перезапуска контейнеров.

## Проверено

- `cargo check --locked --all-targets` и `cargo test --locked --all-targets`
  на Rust 1.88;
- production `tsc -b && vite build`;
- 44 web-теста;
- zero-config bootstrap contract с чистой frontend-сборкой;
- отдельный devctl gate собирает production backend/web images до commit и push;
- Android mobile.9: TypeScript, CRUD contract, 40 Jest-тестов и Expo Android
  export. Нативная Gradle/APK-сборка остаётся проверкой на машине с Android SDK.

## Обновление

Патч рассчитан на `v1.0.0-beta.11`. Во время применения devctl сначала соберёт
production images, затем сам запустит локальный UI-установщик и отправит commit.
Работающий web должен показать beta.12 без отдельной CLI-команды. Если updater
был заблокирован внешним процессом, безопасный ручной fallback —
`python bootstrap.py watch-updates`.
