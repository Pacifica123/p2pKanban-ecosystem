# p2pKanban v1.0.0-beta.8

## Главное изменение

Удаление карточки теперь имеет две явные области:

- «Скрыть здесь» убирает карточку только с текущего узла и допускает возврат;
- «Удалить везде» создаёт durable tombstone и распространяет зашифрованный
  `card.delete` через roaming-журнал.

Tombstone сильнее любого старого `card.put` и bootstrap-снимка. Миграция
`0014` также публикует удаления, сделанные старыми версиями, поэтому после
обновления исправляется уже наблюдавшийся сценарий ПК1 → ПК2.

## Совместимые клиенты

- web/backend: `1.0.0-beta.8`;
- Android: `1.5.0-mobile.6`.

Для честной проверки оба web-узла и Android нужно обновить до этих версий.
Старые клиенты не понимают `card.delete` и не могут гарантировать глобальное
удаление.

## Проверка после обновления

1. На ПК1 создать карточку и дождаться её появления на ПК2.
2. На ПК1 выбрать «Скрыть здесь»: ПК1 скрывает карточку, ПК2 продолжает её
   показывать; на ПК1 карточка возвращается из списка «Скрытые здесь».
3. На ПК1 выбрать «Удалить везде» и дождаться reconnect ПК2.
4. Убедиться, что карточка исчезла на ПК2 и не вернулась после повторного pull.
5. Повторить глобальное удаление Android → web при недоступном coordinator, но
   доступных relay.

## Известная граница

Явной глобальной restore-операции в beta.8 нет. Это не мешает локальному
возврату после «Скрыть здесь», но tombstoned карточка не восстанавливается из
старой копии автоматически.
