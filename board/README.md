# Самоприменимая доска экосистемы

`board.json` — доска, на которой экосистема ведёт собственную работу. Это
обычный переносимый файл доски p2pKanban (`p2p_planner_bundle` v1,
`portable_export`, одна доска), поэтому его открывает сам продукт.

## Как открыть доску в продукте

| Направление | Как | Что важно |
|---|---|---|
| web | список досок нужного workspace → «Импорт доски из JSON» → «Создать копию» | web создаёт копию с новыми ID; комментарии получат текущего автора |
| abl | импорт переносимой доски (A11) | только в пустой профиль; исходные ID сохраняются |
| mobile | пока нельзя: импорт ещё не перенесён из web | карточка «Импорт доски в Android» |

Источник истины — файл в репозитории. Копия в продукте — способ посмотреть и
подумать; изменения возвращаются в репозиторий патчем.

## Колонки-статусы

| Колонка | Когда карточка здесь |
|---|---|
| Идеи | сырая мысль или наблюдение; не обязательство |
| Обдумать | нужна стратегия, ADR или решение владельца до кода |
| Готово к патчу | понятны направление, объём, проверка и критерий готовности |
| В работе | делается текущей серией патчей; не больше двух карточек |
| Ждёт хоста | код и детерминированные проверки есть, нужна приёмка на телефоне, Arch или Docker |
| Сделано | принято; в комментарии есть `patchId` |
| Отложено | сознательно не сейчас; в описании сказано почему |

Карточка движется слева направо, но может вернуться: из «Ждёт хоста» в
«В работе», если хост нашёл ошибку. Из «Сделано» карточки не возвращаются:
новая проблема — новая карточка.

## Метки

У каждой карточки есть хотя бы одна метка направления: `web`, `mobile`, `abl`,
`devctl` или `экосистема`. Дополнительно: `контракт` (меняет связь между
направлениями), `риск`, `долг`.

## Описание карточки

```text
Зачем: какую проблему это решает.

Готово, когда: проверяемый результат.

(необязательно) Ограничения, принципы, почему не сейчас.
```

## Обновление в каждом патче

Обязательно (проверяется `tools/ecosystem/check_board.py --require-changed`):

- `origin.boardRevision` увеличен на 1;
- `origin.lastPatchId` — идентификатор этого патча, `origin.generatedAt` — его время;
- файл остаётся корректным переносимым bundle для web и abl.

По смыслу (проверяется ревью): карточка патча сдвинута или создана, к ней
добавлен комментарий `patch <patchId>: что стало истинным`, сделанные пункты
чек-листа отмечены. Счётчики в `manifest.json.summary.entityCounts` должны
совпадать с содержимым.

Новые ID — UUID (предпочтительно v7, как в продукте). ID существующих
сущностей не меняются: по ним доска связывается с историей патчей.
