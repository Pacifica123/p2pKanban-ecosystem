# `p2p-kanban-launcher-entry/1` — объявление направления для лаунчера

Статус: описан 2026-10-20 (патч `2026-10-20-ecosystem-launcher-entry-contract`).
Порядок: контракт (корень) → web → abl; mobile команд не объявляет (APK
приходит из EAS, E-ADR-004 п.6). Потребитель — `launcher/`. Решение —
[E-ADR-004](../../../docs/ecosystem/adr/E-ADR-004-ecosystem-launcher.md) п.3.

Направление кладёт в свой каталог файл `launcher.json`: какие свои команды
лаунчер может выполнить, какие настройки показать в окне и как спросить, что
установлено. Лаунчер **ничего не знает** об устройстве направления сверх этого
файла: шаги развёртки остаются в направлении, лаунчер только нажимает кнопки,
которые направление само нарисовало.

Эталон — `launcher_entry_check`, `launcher_command` и `launcher_status` в
[`tools/ecosystem/contract_ref.py`](../../../tools/ecosystem/contract_ref.py);
схемы — [`schema/`](schema/); векторы — [`vectors/`](vectors/).

## Правило безопасности: только свои Python-скрипты

- `argv[0]` любого действия — ровно `{python}`. Лаунчер подставляет свой
  интерпретатор (Python 3.11+, тот же, которым запущен сам).
- `argv[1]` — относительный путь к `.py` внутри каталога направления: без `/` в
  начале, без буквы диска, без `..`.
- Остальные аргументы — буквальные строки без управляющих символов и без
  `{` `}`. Единственная подстановка — `{value}` в `options`, и только целым
  аргументом.
- Каталог запуска — каталог направления. Оболочки нет: лаунчер передаёт `argv`
  процессу как список, поэтому значения настроек не интерпретируются.
- Значение настройки проверяется до запуска по её объявлению (порт в границах,
  `choice` из списка). Ошибка — отказ `bad-value`, процесс не запускается.

Направлению, которому нужно что-то, кроме Python (Docker, pacman, makepkg),
нужен свой Python-скрипт, который это вызывает. Так команда остаётся
кроссплатформенной и проверяемой тестами направления, а лаунчер — без знания о
чужих инструментах.

## Файл

```json
{
  "schema": "p2p-kanban-launcher-entry/1",
  "component": "web",
  "settings": [
    {"id": "port", "label": "Порт", "type": "port", "default": null, "help": "пусто — первый свободный от 8080"},
    {"id": "listen", "label": "Доступ", "type": "choice", "default": "local",
     "choices": [{"value": "local", "label": "только этот компьютер"}, {"value": "lan", "label": "локальная сеть"}]}
  ],
  "actions": [
    {"id": "install", "label": "Установить и запустить",
     "argv": ["{python}", "bootstrap.py", "start", "--no-open"],
     "options": [{"setting": "port", "argv": ["--port", "{value}"]}, {"setting": "listen", "argv": ["--listen", "{value}"]}],
     "dryRun": ["--dry-run"], "timeoutSeconds": 3600},
    {"id": "status", "label": "Состояние", "argv": ["{python}", "bootstrap.py", "status", "--json"], "output": "status"}
  ],
  "profiles": [
    {"id": "second-node", "label": "Второй, тестовый узел", "supported": false, "reason": "…"}
  ]
}
```

| Поле | Правило |
|---|---|
| `component` | id направления в `ecosystem.json`; совпадает с каталогом |
| `settings[].type` | `port` (целое `min`…`max`, по умолчанию 1024…65535, или `null` — «выберет направление»), `choice` (одно из `choices[].value`), `bool` |
| `settings[].default` | проходит те же правила; без него — `null` (`bool` — `false`) |
| `actions[].id` | уникален. Лаунчер знает `install`, `start`, `stop`, `update`, `status`, `doctor`, `logs`, `remove`, `launch` и ставит их на свои кнопки; прочие — в меню «Ещё» |
| `actions[].options` | для `port`/`choice` — добавляются, если значение не `null`, `{value}` заменяется значением; для `bool` — добавляются, если `true`, и `{value}` в них нельзя |
| `actions[].dryRun` | аргументы пробного прогона: лаунчер показывает его вывод до настоящего запуска. Без поля пробного прогона у действия нет |
| `actions[].confirm` | текст вопроса; лаунчер не запустит действие без явного «да» |
| `actions[].privileged` | команда сама попросит пароль администратора (`pkexec` или `sudo`); лаунчер предупреждает и запускает как обычно, без своих прав |
| `actions[].detached` | команда запускает приложение и сразу возвращается |
| `actions[].output` | `text` (по умолчанию) или `status` — только у `status` |
| `actions[].timeoutSeconds` | 1…86400, по умолчанию 600 |
| `profiles[]` | варианты установки (E-ADR-004 п.9). `supported: true` — `action` из `actions`, `ask` — какие настройки спросить, `values` — что подставить; `supported: false` — обязательна `reason`, лаунчер показывает вариант серым с ней |

Действие `status` обязательно: без него лаунчер не знает, что установлено.

Порядок аргументов: `argv`, затем `options` в порядке объявления, затем `dryRun`.

Коды отказа объявления: `wrong-schema`, `bad-component`, `bad-setting`,
`duplicate-id`, `no-actions`, `bad-action`, `bad-argv`, `bad-placeholder`,
`unknown-setting`, `no-status`, `bad-profile`. Объявление с отказом лаунчер
не исполняет целиком и показывает направление «только инструкция» с причиной.
Коды отказа команды: `unknown-action`, `bad-value`, `no-dry-run`.

## Ответ `status`

Код выхода 0 и в stdout ровно один JSON-объект ([схема](schema/status.schema.json)):

```json
{"schema": "p2p-kanban-launcher-status/1", "component": "web",
 "installed": true, "running": true, "version": "2.1.0",
 "revision": "<40 hex: коммит монорепозитория установки>",
 "url": "http://127.0.0.1:8080", "values": {"port": 8080, "listen": "local"},
 "detail": "узел отвечает", "problems": []}
```

| Поле | Правило |
|---|---|
| `installed` | установлено ли на этой машине |
| `running` | `true`/`false`; `null` — неизвестно (Docker не запущен, у приложения нет фонового процесса) |
| `revision` | полный SHA коммита, из которого собрана установка; `null`, если неизвестен |
| `url` | `http://` или `https://`; лаунчер показывает кнопку «Открыть» |
| `values` | текущие значения объявленных настроек: лаунчер подставляет их в окно настроек |
| `problems` | строки для пользователя: чего не хватает |

Лаунчер сводит ответ к `state`: `absent`, `installed`, `running`, `stopped`,
`broken` (код выхода не 0 — `exit-code`; не JSON, чужой `component`, неверное
поле — `bad-output`). Неизвестные настройки и недопустимые значения в `values`
отбрасываются, а не роняют ответ. `status` не должен ничего менять и
запускать: лаунчер вызывает его при каждом обновлении окна.

**Сверка с `main`.** Установка «актуальна», если последний коммит `main`,
менявший каталог направления, — предок `revision` или равен ему; это считает
лаунчер, направление сообщает только `revision`.

## Как направление пользуется контрактом

Патч направления кладёт `launcher.json`, реализует `status` и заполняет
`implementations.<направление>` в [compatibility.json](../../compatibility.json).
`check_contracts.py` проверяет каждый `launcher.json` из `ecosystem.json`
эталоном и схемой и требует, чтобы скрипт каждого действия существовал.
Лаунчер реализует контракт сам (`launcher/launcher_app/entry.py`) и сверяется
с [векторами](vectors/).
