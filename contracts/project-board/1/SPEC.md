# `p2p-kanban-project-board/1` — доска проекта, встроенная в клиенты

Статус: описан 2026-10-17 (патч `2026-10-17-ecosystem-project-board-contract`).
Порядок реализации: web (узел и web UI) → mobile → abl. Решение и его
причины — [E-ADR-003](../../../docs/ecosystem/adr/E-ADR-003-project-board-in-clients.md).

Доска, на которой экосистема ведёт свою работу (`board/board.json`), видна в
каждом клиенте сразу после установки, без импорта. Подключение второго узла,
телефона или abl не создаёт её копий: доска проекта **не входит в данные
пользователя и не синхронизируется**. Каждый клиент держит несколько её
версий-кандидатов и показывает старшую.

## Что такое доска проекта

Доска проекта — файл переносимой доски `p2p_planner_bundle` v1
(`portable_export`, одна доска) байт в байт, как он лежит в репозитории. Новых
полей контракт не вводит. Клиент узнаёт её по признакам
([`project_board_summary`](../../../tools/ecosystem/contract_ref.py) в эталоне):

| Признак | Значение |
|---|---|
| `manifest.json.format`, `formatVersion`, `bundleKind`, `scopeKind` | `p2p_planner_bundle`, `1`, `portable_export`, `board` |
| `manifest.json.boardId` | `01a10d38-f902-7665-8612-3e74278ceafa` — постоянный id доски проекта |
| `manifest.json.workspaceId` | `01a10d38-f901-746d-92f7-10598bb1cc42` |
| `origin.selfHosted` | `true` |
| `origin.boardRevision` | целое ≥ 1; растёт на 1 с каждым патчем (`check_board.py --require-changed`) |
| `origin.lastPatchId` | непустая строка: патч, который сделал эту ревизию |
| размер | не больше 10 МиБ |

Всё, что не проходит, — не доска проекта, с кодом отказа: `not-json`,
`too-large`, `wrong-format`, `foreign-board` (другой id или не `selfHosted`),
`no-revision`. Для недоступного источника клиент пишет `unreachable` или
`http-error`. Экспорт пользовательской копии этой доски из web получает новые
id и не `selfHosted`, поэтому доской проекта не считается.

Сводка ([summary.schema.json](schema/summary.schema.json)): `revision`,
`lastPatchId`, `generatedAt`, `sha256` байтов файла и `bytes`. По ней
кандидаты сравниваются без разбора всей доски.

## Источники

| Источник | Что это | У кого |
|---|---|---|
| `build` | копия файла, которую направление положило в свою сборку (путь — `projectBoard` в `ecosystem.json`) | у всех |
| `cache` | последняя доска, полученная с узла, сохранённая на устройстве | mobile, abl |
| `node` | `GET /api/v1/project-board` подключённого web-узла | mobile, abl, web UI |
| `upstream` | `board/board.json` ветки `main` канала обновления узла (тот же репозиторий GitHub, что у автообновления) | только web-узел |

Ни один источник не пишет в доску. Клиент не отправляет доску проекта никуда,
кроме собственного кеша.

## Выбор

[`select_project_board`](../../../tools/ecosystem/contract_ref.py), векторы
[selection.json](vectors/selection.json):

1. отброшенные кандидаты попадают в `rejected` с кодом;
2. из годных побеждает **старшая `revision`**: ревизии идут строго по патчам
   одного репозитория, поэтому старшая содержит все прежние изменения;
3. одна ревизия, разные байты (две ветки разошлись) — побеждает меньший
   `sha256`, `conflict: true`; клиент показывает предупреждение «две разные
   доски ревизии N»;
4. одна ревизия, одинаковые байты — побеждает первый по списку клиента;
   клиенты перечисляют `build`, `cache`, `node`, `upstream` в этом порядке,
   поэтому актуальная сборка так и называется: «из сборки»;
5. `behind` перечисляет отставшие источники: «узел: ревизия 32».

Слияния карточек нет и не нужно: любая ревизия целиком заменяет более старую.

## Изоляция

Доска проекта — справочный документ, а не рабочая доска. Клиент обязан:

- не записывать её в базу узла, профиль abl или локальную реплику mobile как
  пространство или доску пользователя;
- не публиковать её в relay: никаких событий `roaming/1`, записей
  `keyring/1`, `account-ring/1`, активности и `board.activity`;
- не переносить её через `web-node-link/1` и привязку устройства;
- не давать её редактировать: нет кнопок создания, перемещения, комментариев;
- показывать её отдельным пунктом «Доска проекта», не в списке пространств.

Если человек хочет черновик, он делает обычный импорт как копию
(web — «Создать копию»): у копии новые id, и это уже его доска.

Поэтому повторное подключение узлов не может её размножить: в синхронизацию
она не входит, а постоянный id нужен только чтобы узнать файл.

## Web-узел

| Маршрут | Ответ |
|---|---|
| `GET /api/v1/project-board` | байты выбранной узлом доски (`build` или `upstream`), `content-type: application/json`, `etag: "<sha256>"`; при `if-none-match` с тем же значением — `304` |
| `GET /api/v1/project-board/summary` | в обычной обёртке узла `{"data": …}` — [node-summary.schema.json](schema/node-summary.schema.json): что отдаётся сейчас, сводка копии из сборки, состояние проверки `upstream` |

Маршруты не требуют входа: содержимое совпадает с публичным репозиторием, и
телефон должен видеть доску до входа и на чужом узле. Узел выбирает между
`build` и `upstream` тем же правилом. `upstream` узел проверяет при запуске и
не чаще раза в час, по тому же адресу репозитория и ветке, что автообновление;
отказ сети не мешает отдавать `build`, а негодный ответ не вытесняет последнюю
годную доску. Ответ на доску несёт заголовок `x-p2p-kanban-project-board:
rev=<N>; patch=<id>; source=<build|upstream>` (и `; conflict`). Проверку
`upstream` выключает переменная узла `P2PKANBAN_PROJECT_BOARD_UPSTREAM=off`.

## Что показывает клиент

Над доской одна строка: `Ревизия 33 · 2026-10-17-ecosystem-project-board-contract ·
из сборки` (или «с узла 192.168.0.101:8082», «из кеша, узел недоступен», «с
GitHub»). Если есть `behind` — «в сборке ревизия 32», если `conflict` —
предупреждение. Карточки, метки, чек-листы и комментарии видны как в обычной
доске, без кнопок изменения.

## Копия в сборке

Копии в направлениях — те же байты, что `board/board.json` на момент патча,
который их обновил. Обновляет их `python -B tools/ecosystem/project_board.py
vendor <направление>`; `project_board.py check` проверяет, что каждая копия —
доска проекта и не новее корневой, и печатает, на сколько ревизий она отстала.
Отставание копии — не ошибка: узел догоняет `upstream`, телефон и abl
получают доску с узла. Патч направления по умолчанию обновляет свою копию.

## Как меняется контракт

Новые необязательные поля в `origin` или в сводке узла допустимы в этой
версии: читатель их игнорирует. Смена постоянного id или правила выбора —
новая версия `project-board/2`.
