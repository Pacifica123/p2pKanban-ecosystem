# `p2p-kanban-error-report/1` — подробности ошибки

Статус: описан 2026-10-07 (патч `2026-10-07-ecosystem-error-report-contract`).
Порядок реализации: web (узел и web UI) → mobile → abl.

Ошибка вроде «Импорт остановлен… Request failed with 502» не содержит ничего,
что можно передать дальше: ни стадии, ни ответа сервера, ни строки лога, ни
версии. Этот контракт — «сборщик логов»: у каждой ошибки, которую видит
человек, есть кнопка **«Скопировать подробности»**, и текст под ней одинаковой
формы в web, mobile и abl. Его хватает, чтобы разобрать ошибку без доступа к
устройству, и в нём нет секретов.

Контракт состоит из двух частей:

1. **отчёт** — что копирует кнопка (клиенты: web UI, mobile, abl);
2. **ответ узла с ошибкой** — что web-узел обязан отдать, чтобы отчёт клиента
   можно было связать со строкой журнала узла (производит web, читают все).

## Отчёт

Отчёт — JSON-объект ([report.schema.json](schema/report.schema.json)):

| Поле | Смысл |
|---|---|
| `protocol` | `"p2p-kanban-error-report/1"` |
| `reportId` | `er-` + 16 случайных hex; создаёт клиент |
| `at` | время ошибки, UTC, ISO 8601 с миллисекундами |
| `software` | `{direction: web, mobile или abl, version, build, commit}` — кто упал. `build`: web — отпечаток образа, mobile — versionCode, abl — версия пакета; `commit` — коммит монорепозитория. Неизвестное — `null`, а не пустая строка: текст скажет «неизвестен» |
| `platform` | браузер, версия Android или дистрибутив и WebKitGTK |
| `screen`, `operation`, `stage` | экран, операция, шаг операции («создание комментария 2/6») |
| `message` | то, что увидел человек |
| `error` | `{kind, name, detail}`; `kind`: `http`, `network`, `timeout`, `native`, `storage`, `validation`, `internal`, `unknown` |
| `http` | `{method, path, status, requestId, errorId, body}` или `null`; `status: 0` — ответа не было |
| `peer` | узел, с которым говорил клиент, по заголовку `x-p2p-kanban-node` последнего ответа: `{direction: "web", version, build, commit}` или `null` |
| `logs` | последние строки кольцевого буфера журнала клиента, старые первыми |
| `redacted` | сколько значений вырезано |

`peer` делает видимым смешение версий: старый APK, который говорит с новым
узлом, сам пишет в отчёте обе версии.

### Нормализация (`build_report` в эталоне)

Клиент собирает сырой отчёт и перед показом и копированием нормализует его:

1. переводы строк `\r\n` и `\r` → `\n` во всех текстовых полях;
2. вырезание секретов (ниже) в `message`, `stage`, `error.detail`, `http.path`,
   `http.body` и в каждой строке `logs`;
3. `logs`: берутся последние 50 строк, переводы строк внутри строки → пробел;
4. обрезка по пределам: если длина больше предела, остаётся `предел − 1`
   кодовых точек и `…`.

| Поле | Предел, кодовых точек |
|---|---|
| `message` | 1000 |
| `screen`, `operation`, `stage`, `platform`, `error.name` | 200 |
| `error.detail` | 2000 |
| `http.path` | 500 |
| `http.body` | 4000 |
| строка `logs` | 500 |

**Длина считается в кодовых точках Unicode**, а не в байтах UTF-8 и не в
единицах UTF-16. Обрезка по байтам однажды уже роняла узел на кириллице (502
при копии доски); обрезка по UTF-16 разрезает эмодзи. В JavaScript это
`Array.from(text)`, в Rust `chars()`, в Python `str`.

### Вырезание секретов (`redact` в эталоне)

Правила применяются к строке по порядку; каждая замена увеличивает `redacted`
на 1. Регулярные выражения даны в синтаксисе, общем для Python, JavaScript и
Rust; имена ключей сравниваются без учёта регистра.

| # | Что | Шаблон | Замена |
|---|---|---|---|
| 1 | токен в заголовке | `bearer\s+[A-Za-z0-9._~+/=-]+` | `Bearer [скрыто]` |
| 2 | JWT | `eyJ[A-Za-z0-9_-]{5,}\.[A-Za-z0-9_-]{5,}\.[A-Za-z0-9_-]*` | `[скрыто:jwt]` |
| 3 | секретный ключ Nostr | `nsec1[02-9ac-hj-np-z]{20,}` | `[скрыто:nsec]` |
| 4 | пароль в URL | `://[^/\s:@]+:[^/\s@]+@` | `://[скрыто]@` |
| 5 | пара «ключ = значение» | см. ниже | значение → `[скрыто]` |

Правило 5: ключ — слово из `[A-Za-z0-9_-]`, в котором есть `password`,
`passwd`, `secret`, `token`, `apikey`, `api_key`, `api-key`, `privatekey`,
`private_key`, `passphrase`, `mnemonic`, `boardkey`, `board_key`, `masterkey`,
`master_key` или `cookie`, перед ним начало строки или символ не из
`[A-Za-z0-9]`; затем необязательные `\` и `"`, `:` или `=` с пробелами; затем
значение одного из трёх видов:

```text
(^|[^A-Za-z0-9])
([A-Za-z0-9_-]*(?:password|passwd|secret|token|apikey|api_key|api-key|privatekey|private_key|passphrase|mnemonic|boardkey|board_key|masterkey|master_key|cookie)[A-Za-z0-9_-]*)
(\\?"?[ \t]*[:=][ \t]*)
(\\"(?:[^\\]|\\[^"])*?\\"|"(?:[^"\\]|\\[\s\S])*"|[^\s,;&}"\\]+)
```

Значение в кавычках заменяется вместе с кавычками своего вида (`"[скрыто]"`
или `\"[скрыто]\"`), без кавычек — на `[скрыто]`. Значение, которое уже
`[скрыто…]` или начинается с `Bearer`, не трогается и не считается: повторная
нормализация ничего не меняет.

Сознательно **не** вырезаются: публичные ключи (64 hex без имени-ключа),
адреса relay и узла, id досок и карточек, текст карточек. Отчёт уходит
владельцу, а не в публичный трекер; цель — не утечь ключами, а не обезличить.
Ложные срабатывания допустимы (`tokens: 3 of 5` → `tokens: [скрыто] of 5`):
лучше спрятать лишнее, чем показать ключ.

### Текст кнопки (`render_report` в эталоне)

```text
p2pKanban: подробности ошибки
Отчёт: er-… · 2026-10-06T07:41:12.204Z
Программа: web 2.1.0 · сборка 8087da08253b · коммит 520e41c…
Платформа: …
Где: Импорт доски → Создать копию доски → создание комментария 2/6
Сообщение: …
Ошибка: http · ApiError · Request failed with 502
HTTP: POST /api/v1/… → 502 · запрос … · ошибка узла …
Узел: web 2.2.0 · сборка … · коммит неизвестен
Ответ узла:
  <тело ответа, каждая строка с отступом в два пробела>
Скрыто значений: 3
Журнал (3 последних строк):
  <строка журнала>
--- p2p-kanban-error-report/1 ---
{"at":"…",…}
```

Строки «Платформа», «Где», «HTTP», «Узел», «Ответ узла», «Скрыто значений»,
«Журнал» пропускаются, если данных нет. Многострочные значения продолжаются с
отступом в два пробела. Последняя строка — каноническая форма JSON отчёта
(ключи по алфавиту, без пробелов, UTF-8 без `\u`-экранирования не-ASCII) и
перевод строки. **Источник истины — JSON после разделителя**: текст выше для
человека, а машина (или нейросеть) читает отчёт обратно без разбора русского
текста. Вектор [reports.json](vectors/reports.json) фиксирует текст байт в байт.

### Кольцевой буфер журнала

Каждый клиент держит в памяти последние строки своего журнала (не меньше 50,
сколько больше — решает направление) и отдаёт их в `logs`. Рекомендуемая форма
строки: `<время UTC> <уровень> <источник>: <текст>`. Буфер не пишется на диск
ради отчёта и не уходит с устройства сам: только по кнопке и только в буфер
обмена.

## Ответ web-узла с ошибкой

Тело ответа с ошибкой остаётся прежним (`{"error": {"code", "message", "details"}}`)
и получает поле `errorId` ([http-error.schema.json](schema/http-error.schema.json)):

- **Ответ 5xx, который выдал сам узел, несёт `errorId`** (UUID v7) в теле и в
  заголовке `x-p2p-error-id`. Та же строка записана в журнал узла полем
  `error_id`, поэтому её находит `python bootstrap.py logs` или `docker logs`.
- **Паника обработчика превращается в такой же ответ 500 с `errorId`**, а не в
  оборванное соединение. Обрыв шлюз превращает в 502 без тела, и тогда ни у
  клиента, ни у узла нет общей зацепки.
- 4xx могут не нести `errorId`: это ответ на запрос, а не сбой узла.

Каждый ответ узла (в том числе успешный) несёт заголовок версии:

```text
x-p2p-kanban-node: 2.2.0; build=3f1c9a2b7d10; commit=<40 hex или unknown>
```

Клиент запоминает последний такой заголовок и кладёт его в `peer`
(`unknown` → `null`). У узла старой версии заголовка нет: `peer: null`, и это
тоже видно в отчёте. Вектор: [http-error.json](vectors/http-error.json).

## Как направление пользуется контрактом

Тесты направления читают `contracts/error-report/1/vectors/*.json` и требуют:

- `redact(input) == expected` и то же число замен для каждого случая `redact.json`;
- `truncate` из `redact.json` совпадает;
- для каждого случая `reports.json`: нормализация `input` даёт `expectedReport`,
  а текст из `expectedReport` равен `expectedText` байт в байт;
- web-узел: тело 5xx проходит `http-error.schema.json` и несёт `errorId`;
  заголовок `x-p2p-kanban-node` разбирается в `expectedNode`.

## Чего `/1` не делает

- Не отправляет отчёт никуда сам: только буфер обмена по нажатию человека.
- Не собирает журнал узла с клиента: клиент даёт `errorId`, а строку журнала
  узла владелец берёт на узле (`bootstrap.py logs`).
- Не обезличивает содержимое досок: только ключи, токены и пароли.
